# FastAPI Basics, Week 1 Day 2 — маршруты и HTTP methods

## Зачем нужен отдельный разговор про маршруты
Как только у сервиса появляется больше одного действия, тебе уже недостаточно “какой-то endpoint что-то возвращает”.

Нужно чётко понимать:
- по какому URL клиент приходит;
- какой HTTP method он использует;
- какое действие на сервере это означает.

Именно это и есть API-контракт на базовом уровне.

## Как правильно думать про URL и method
Полезная схема:
- URL отвечает на вопрос: **с каким ресурсом мы работаем**;
- HTTP method отвечает на вопрос: **что мы хотим сделать с этим ресурсом**.

Примеры:
- `GET /users` — получить список пользователей;
- `GET /users/42` — получить одного пользователя;
- `POST /users` — создать пользователя;
- `DELETE /users/42` — удалить пользователя.

То есть один и тот же ресурс `/users` может участвовать в разных действиях в зависимости от method.

## Какие методы нужно понимать в первую очередь
На базовом уровне тебе достаточно уверенно различать:
- `GET` — чтение данных;
- `POST` — создание нового объекта или запуск операции создания;
- `PATCH` — частичное изменение объекта;
- `DELETE` — удаление объекта.

Не нужно усложнять это раньше времени. Сначала важно научиться видеть смысл контракта.

## Как выглядит маршрут в FastAPI
```python
@app.get('/users')
def list_users():
    ...

@app.get('/users/{user_id}')
def get_user(user_id: int):
    ...

@app.post('/users')
def create_user():
    ...
```

В этом фрагменте видно две важные вещи:
- один и тот же префикс `/users` может означать список или detail view;
- разные methods на похожих путях — это разные действия.

## Collection route и detail route
Это базовое различие, которое нужно быстро усвоить.

`/users`
- collection route;
- работает со списком сущностей.

`/users/{user_id}`
- detail route;
- работает с одной конкретной сущностью.

Если это не различать, API очень быстро становится нечитаемым.

## Почему не стоит называть пути действиями
Плохой стиль для базового CRUD API:
- `/getUsers`
- `/createUser`
- `/deleteUser`

Гораздо сильнее читается ресурсная модель:
- `/users`
- `/users/{user_id}`

Потому что действие уже выражено через HTTP method.

## Где ошибаются чаще всего
- Используют `POST` почти для всего подряд.
- Путают список и одну сущность.
- Называют URL действиями вместо ресурсов.
- Не думают, как будет выглядеть API, когда сущностей станет больше.

## Что нужно вынести из урока
Перед практикой ты должен понимать:
1. разницу между collection route и detail route;
2. почему URL и method вместе образуют контракт;
3. почему ресурсный стиль API обычно лучше, чем набор глагольных URL.
