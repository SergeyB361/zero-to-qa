# FastAPI Basics, Week 1 Day 1 — ASGI и роль FastAPI

## Зачем вообще нужен FastAPI
Когда ты переходишь от скриптов и библиотек к backend-сервису, тебе нужен framework, который умеет:
- принять HTTP-запрос;
- понять, какой endpoint должен его обработать;
- вызвать Python-код;
- вернуть HTTP-ответ обратно клиенту.

FastAPI решает именно эту задачу. Он не заменяет Python и не пишет бизнес-логику за тебя. Он даёт удобный слой, чтобы описывать API как обычные Python-функции.

## Как устроен минимальный FastAPI-сервис
Полезно держать в голове такую схему:

```text
client -> uvicorn -> FastAPI app -> endpoint function -> HTTP response
```

Что здесь делает каждый слой:
- `client` отправляет HTTP-запрос;
- `uvicorn` поднимает ASGI-сервер и передаёт запрос приложению;
- `FastAPI()` создаёт объект приложения;
- декоратор вроде `@app.get('/health')` связывает URL и Python-функцию;
- endpoint-функция возвращает данные, а framework превращает их в HTTP-ответ, чаще всего в JSON.

## Что такое ASGI без лишней теории
На этом уровне достаточно понимать следующее:
- ASGI — это интерфейс, по которому Python-веб-приложение общается с сервером;
- `uvicorn` — ASGI-сервер;
- FastAPI — ASGI-приложение.

То есть `uvicorn` и FastAPI — не одно и то же.

`uvicorn` запускает приложение.
FastAPI описывает поведение приложения.

## Что реально делает `app = FastAPI()`
Эта строка создаёт приложение и регистрирует в нём маршруты, зависимости, middleware, документацию и остальную конфигурацию.

После этого ты можешь писать:

```python
app = FastAPI()

@app.get('/health')
def healthcheck() -> dict[str, str]:
    return {'status': 'ok'}
```

Смысл такой:
- `GET /health` приходит в приложение;
- FastAPI знает, что нужно вызвать функцию `healthcheck`;
- результат функции превращается в JSON-ответ.

## Почему route-функция выглядит как обычная Python-функция
Это одна из сильных сторон FastAPI.

Ты описываешь поведение приложения через обычные функции:
- принимаешь аргументы;
- возвращаешь значения;
- используешь типы;
- выносишь логику в другие функции и классы.

То есть framework не отменяет нормальную Python-архитектуру. Он только добавляет HTTP-слой вокруг неё.

## Что важно не перепутать в первый день
Чаще всего путают такие вещи:
- `uvicorn` и FastAPI;
- route и бизнес-логику;
- JSON-ответ и обычный Python-словарь.

Правильная mental model такая:
- route — это входная точка HTTP;
- Python-код внутри route — это уже твоя логика;
- `dict` на выходе — это не “магический объект FastAPI”, а просто данные, которые framework сериализует в JSON.

## Где ошибаются чаще всего
- Пытаются понять ASGI слишком глубоко до того, как разобрались с обычными route-ами.
- Кладут всю логику прямо в endpoint и не оставляют места для дальнейшей структуры.
- Думают, что FastAPI “сам решит архитектуру”. Не решит: архитектуру по-прежнему задаёшь ты.

## Что нужно вынести из урока
Перед практикой ты должен уметь ответить на 3 вопроса:
1. зачем нужен объект `app = FastAPI()`;
2. чем отличается сервер `uvicorn` от самого приложения;
3. как URL и Python-функция связываются через route decorator.
