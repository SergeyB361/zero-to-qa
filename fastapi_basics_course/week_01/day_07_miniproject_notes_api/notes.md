# FastAPI Basics, Week 1 Day 7 — Мини-проект Notes API

## Зачем этот мини-проект нужен именно здесь
После первых шести дней у тебя уже есть базовые детали FastAPI:
- приложение;
- routes;
- path params;
- request body;
- response models;
- errors.

Теперь важно собрать их в один маленький, но цельный сервис.

## Что это за проект
`Notes API` — это учебный API заметок без базы данных и без ORM.

Это осознанное ограничение.
Сейчас цель не в persistence, а в том, чтобы почувствовать структуру HTTP-контракта.

## Что именно должен показать проект
В проекте должны быть:
- list route;
- detail route;
- create route;
- delete route;
- request model;
- response model;
- `404` для not found;
- in-memory storage.

То есть это маленький CRUD-like сервис, но уже с нормальной формой API.

## Почему storage остаётся in-memory
Потому что на этом этапе база данных только отвлечёт от главного.

Сейчас нужно закрепить:
- как проектировать endpoints;
- как оформлять вход и выход;
- как возвращать ошибки;
- как строить минимально читаемый сервис.

Если сюда рано добавить ORM, миграции и SQL, фокус разъедется.

## Как лучше собирать проект
Хороший порядок такой:
1. определить модель заметки на выходе;
2. определить модель создания на входе;
3. сделать list и detail routes;
4. добавить create route;
5. добавить delete route;
6. только потом полировать ответы и ошибки.

## Что считается хорошим результатом
Хороший результат — это не “как можно больше фич”, а:
- предсказуемые routes;
- чистые модели;
- понятный `404`;
- код, который читается без объяснений автора.

## Где ошибаются чаще всего
- Сразу пытаются усложнить проект auth, search, update, tags и прочими функциями.
- Не различают входную и выходную модели.
- Делают create route без `201 Created`.
- Возвращают not found как текст вместо нормальной HTTP-ошибки.

## Что нужно вынести из мини-проекта
После выполнения ты должен уже уметь собрать маленький API на FastAPI без ощущения, что framework всё ещё “магический”.
