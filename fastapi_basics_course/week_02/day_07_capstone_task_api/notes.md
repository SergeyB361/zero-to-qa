# FastAPI Basics, Week 2 Day 7 — Capstone Task API

## Зачем нужен capstone в конце трека
Отдельные уроки дают инструменты. Capstone проверяет, можешь ли ты собрать из них цельный сервис.

Здесь задача уже не в том, чтобы “знать про `response_model`” или “помнить синтаксис `Depends`”, а в том, чтобы использовать эти вещи вместе осмысленно.

## Что это за проект
`Task API` — это учебный backend-сервис задач.

Он всё ещё intentionally простой:
- без БД;
- без ORM;
- без сложной auth-системы;
- без production deployment.

Но он уже должен выглядеть как настоящий маленький backend, а не как набор разрозненных примеров.

## Что проект должен показать
Хороший capstone здесь демонстрирует:
- resource-oriented routes;
- request и response models;
- error handling;
- service + repository separation;
- одну общую auth dependency;
- читаемую структуру кода.

То есть главный результат — не количество функций, а инженерная связность.

## Почему storage всё ещё in-memory
Потому что этот курс про FastAPI basics, а не про persistence stack.

Если сейчас добавить ORM, SQLAlchemy, миграции и Postgres, фокус размоется.

На этом этапе важнее доказать, что ты умеешь:
- проектировать API-контракт;
- отделять HTTP-слой от логики;
- собирать маленький сервис без архитектурного хаоса.

## Как лучше собирать capstone
Хороший порядок работы:
1. определить модель задачи;
2. определить endpoint-ы и их роли;
3. описать request/response models;
4. собрать repository;
5. вынести бизнес-логику в service;
6. навесить auth dependency;
7. проверить not found и status codes.

Это лучше, чем хаотично писать route за route без общей модели.

## Что считается сильным результатом
Сильный результат — это сервис, у которого:
- URL читаются предсказуемо;
- вход и выход оформлены явно;
- ошибки сделаны честно;
- route-функции не перегружены;
- структура уже похожа на основу настоящего backend-проекта.

## Где ошибаются чаще всего
- Пытаются рано утащить проект в полноценный production backend.
- Кладут всю логику в route-функции.
- Делают auth-check вручную в каждом endpoint-е.
- Смешивают service и repository без ясной границы.
- Не продумывают error branches и status codes.

## Что нужно вынести из capstone
После выполнения этого проекта ты должен уже уметь собрать маленький FastAPI-сервис без ощущения, что framework остаётся чёрным ящиком.
