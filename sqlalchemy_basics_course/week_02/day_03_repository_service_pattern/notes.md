# Repository и Service Layer поверх ORM

## Когда это нужно
В реальном backend-коде редко хочется, чтобы route напрямую знал про детали ORM-запросов. Обычно SQLAlchemy живёт под repository/service abstraction.

## Как об этом думать
- repository отвечает за доступ к данным;
- service отвечает за бизнес-логику;
- session обычно передаётся извне, а не создаётся хаотично внутри каждого метода.

## Что важно понять
Хороший repository не должен становиться "вторым ORM". Он должен упрощать нужные сценарии, а не прятать всё подряд.
