# Transactions и Session Scope

## Когда это нужно
Как только ORM используется в реальном backend-коде, основной риск — не неправильный `select`, а хаотичная работа с `commit/rollback` и временем жизни `Session`.

## Как об этом думать
`Session` — это рабочий контекст изменения данных. Его scope должен быть понятен:
- один сценарий;
- один unit of work;
- одна точка commit/rollback.

## Что важно понять
- не каждый helper должен вызывать `commit()`;
- rollback нужен, чтобы не оставлять полусломанное состояние;
- в веб-приложении session scope обычно живёт один request.

## Типичные ошибки
- делать `commit()` в каждом repository method;
- переиспользовать одну Session между несвязанными сценариями;
- не закрывать session context.
