# Window functions

## Когда это нужно
Обычная агрегация через `GROUP BY` “схлопывает” строки. Иногда это неудобно: хочется посчитать метрику по группе, но не потерять исходные записи.

Именно для этого и нужны оконные функции.

Они позволяют:
- считать метрики по группе;
- при этом сохранять каждую исходную строку;
- сравнивать строку с её группой, а не только получать итоговую сводку.

## Как об этом думать
Window function — это расчёт “поверх окна строк”.

То есть база смотрит не только на текущую строку, но и на соседние строки внутри заданного набора:
- по всей таблице;
- по группе `PARTITION BY`;
- в определённом порядке `ORDER BY`.

Хороший вопрос перед использованием окна:
- мне нужен итог по группе,
- или мне нужно сохранить каждую строку и добавить к ней дополнительный расчёт?

Если второе — это кандидат на window function.

## Базовый синтаксис
```sql
SELECT
    case_id,
    duration_sec,
    AVG(duration_sec) OVER (PARTITION BY case_id) AS avg_duration_per_case
FROM test_runs;
```

Это читается так:
- для каждой строки `test_runs`;
- посчитай среднюю длительность внутри группы с тем же `case_id`;
- но саму строку не удаляй.

## Чем это отличается от GROUP BY
`GROUP BY` даёт одну строку на группу.

Window function даёт метрику на каждую строку внутри группы.

Это ключевая разница. Новички часто путают именно это.

## Практический смысл
Window functions часто нужны для:
- сравнения строки со средней по группе;
- расчёта метрик по инженеру, кейсу, релизу;
- подготовки ranking и running total сценариев;
- аналитических отчётов без потери деталей.

## Частые ошибки
- использовать окно там, где хватает обычного `GROUP BY`;
- забывать `PARTITION BY` и случайно считать по всей таблице;
- не контролировать `ORDER BY`, когда порядок действительно важен;
- ожидать, что оконная функция уменьшит число строк.

## Что важно понять перед практикой
1. Оконная функция не схлопывает строки.
2. `PARTITION BY` задаёт логические группы.
3. `ORDER BY` внутри окна влияет на вычисление некоторых функций.
4. Окно — это аналитика поверх строк, а не просто альтернатива `GROUP BY`.
