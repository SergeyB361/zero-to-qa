# Мини-проект: аналитические SQL-запросы

## Цель проекта
Собрать набор аналитических SQL-запросов поверх данных о test runs, defects и API checks.

Это уже не отдельная локальная техника, а мини-пакет отчётов, где нужно показать:
- читаемый advanced SQL;
- нормальную декомпозицию сложных запросов;
- умение выбрать подходящий инструмент под метрику.

## Что здесь проверяется
Проект проверяет, умеешь ли ты:
- использовать CTE для промежуточных этапов;
- применять оконные функции, когда надо сохранить строки;
- ранжировать данные по смыслу, а не механически;
- собирать аналитические отчёты, которые реально можно читать.

## Как правильно подходить к проекту
1. Не пиши все запросы подряд без плана.
2. Для каждого отчёта сначала определи:
   - какая исходная таблица главная;
   - нужны ли промежуточные этапы;
   - нужен ли ranking или window;
   - какой порядок важен.
3. Затем пиши запрос по частям.

## Что отличает хороший итоговый скрипт
- запросы названы и структурированы логично;
- промежуточные CTE имеют понятные имена;
- нет лишних вложенностей ради “сложности”;
- каждый отчёт можно коротко объяснить словами.

## Что делать дальше
1. Открой starter SQL-файл и посмотри expected sections.
2. Реализуй запросы по одному.
3. После каждого запроса проверяй не только результат, но и читаемость структуры.
4. В конце приведи весь скрипт к виду, который не стыдно показать на code review.
