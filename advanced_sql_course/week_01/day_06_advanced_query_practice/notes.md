# Практика на продвинутые запросы

## Зачем это нужно
Этот день нужен, чтобы склеить CTE, окна, ранжирование и условные агрегации в реальные аналитические задачи.

## Ключевые идеи
- комбинация advanced-инструментов
- аналитический отчёт
- сначала читаем данные, потом оптимизируем

## Практический фокус
Здесь важнее ясность запроса, чем его “хитрость”. Делай шаги понятными.

## Типичные ошибки
- сразу писать монолитный SQL
- не проверять промежуточные результаты

## Практика
В `practice.sql` реализуй функции:
- `top_slowest_cases` - Верни top-3 test_cases по средней длительности.
- `releases_with_failed_runs` - Верни пары `build_tag:failed_count` только для релизов с ошибками.
- `engineer_failure_share` - Верни пары `engineer:failed_runs`.

## Что дальше
Сначала запусти `examples.sql`, затем доведи функции из `practice.sql` до expected-результатов.
