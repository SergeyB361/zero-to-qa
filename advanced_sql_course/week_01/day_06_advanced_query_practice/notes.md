# Практика: advanced querying

## Цель дня
Сегодня задача не в новой конструкции, а в сборке нескольких advanced SQL-приёмов в одни связные запросы.

Здесь уже нужно уметь выбирать инструмент под задачу:
- CTE;
- окно;
- ranking;
- условную агрегацию;
- `LAG` / `LEAD`.

## Как подходить к таким задачам
Не начинай сразу писать SQL целиком.

Сначала ответь на 3 вопроса:
1. какой итоговый результат нужен по смыслу;
2. какие промежуточные шаги там есть;
3. какой приём лучше решает каждый шаг.

## Хороший workflow
1. Опиши результат обычным языком.
2. Реши, нужен ли промежуточный шаг через CTE.
3. Реши, схлопываются ли строки или их нужно сохранить.
4. Реши, важен ли порядок.
5. Только после этого пиши SQL.

## Частые ошибки
- смешивать несколько advanced-приёмов без необходимости;
- писать “монолитный” запрос без промежуточных имён;
- брать ranking там, где хватает агрегата;
- брать окно там, где нужен просто `GROUP BY`.

## Что считать хорошим решением
Хорошее решение здесь:
- читается сверху вниз;
- использует продвинутые конструкции по делу;
- не содержит лишней магии;
- может быть объяснено вслух шаг за шагом.

## Что делать дальше
1. Сначала прочитай условие каждого задания и перескажи его обычным языком.
2. Потом собери SQL по шагам.
3. После решения сравни: нельзя ли сделать его короче, не потеряв смысл.
