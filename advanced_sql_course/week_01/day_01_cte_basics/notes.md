# CTE: база

## Зачем это нужно
CTE помогает разбить тяжёлый запрос на именованные части. Это делает SQL читаемее и удобнее для отладки.

## Ключевые идеи
- WITH
- именованный промежуточный результат
- разбиение запроса на этапы
- повторное использование логики

## Практический фокус
Используй CTE, когда промежуточный шаг логически важен сам по себе: например сначала собрать failed runs, затем агрегировать или фильтровать их.

## Типичные ошибки
- писать CTE просто ради моды
- раздувать один запрос в пять бесполезных CTE
- терять смысл промежуточных имён

## Практика
В `practice.sql` напиши запросы:
- `failed_runs_per_case` - Верни пары `title:failed_count` через CTE.
- `latest_release_runs` - Верни количество test_runs для последнего релиза.
- `open_defects_per_release` - Верни пары `build_tag:open_defects`.

## Что дальше
Сначала выполни `examples.sql`, затем доведи запросы из `practice.sql` до expected-результатов.
