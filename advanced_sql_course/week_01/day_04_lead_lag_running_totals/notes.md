# LEAD, LAG и running totals

## Когда это нужно
Иногда недостаточно смотреть на строку изолированно. Нужно сравнить её:
- с предыдущей строкой;
- со следующей строкой;
- с накопленным итогом по времени.

Для этого и нужны `LAG`, `LEAD` и running totals.

## Как об этом думать
Это всё задачи про порядок строк.

Главный вопрос здесь не “какую функцию взять?”, а “в каком порядке строка должна сравниваться с соседями?”.

Если порядок задан плохо, расчёт будет бессмысленным.

## Что делает LAG
`LAG()` возвращает значение из предыдущей строки в окне.

Пример:
```sql
LAG(released_at) OVER (ORDER BY released_at)
```

Это значит: для каждой строки покажи значение `released_at` из предыдущей строки по времени.

## Что делает LEAD
`LEAD()` возвращает значение из следующей строки.

Это симметричный инструмент для сценариев “что будет дальше”.

## Что такое running total
Running total — это накопительный итог.

Например:
- количество failed run по мере движения по релизам;
- сумма latency по мере движения по дням;
- общее число событий к текущей точке времени.

## Почему здесь особенно важен ORDER BY
Без правильного `ORDER BY` соседние строки не определены.

То есть:
- `LAG` и `LEAD` без хорошего порядка мало что значат;
- running total без временного или логического порядка тоже теряет смысл.

## Практический смысл
Эти функции полезны для:
- анализа релизной истории;
- time-series отчётов;
- сравнения “текущее значение против предыдущего”;
- аналитики изменений во времени.

## Частые ошибки
- забывать, что без `ORDER BY` нельзя корректно анализировать соседние строки;
- не контролировать, что именно считается “предыдущим” и “следующим”;
- путать простой cumulative sum с агрегацией по всей группе;
- не думать, что будет для первой и последней строки.

## Что важно перед практикой
1. Ясно определить порядок строк.
2. Понять, с чем именно ты сравниваешь текущую строку.
3. Понимать, что `LAG` и `LEAD` не меняют число строк.
4. Понимать, что running total — это накопление по уже заданному порядку.
