# Recursive CTE

## Когда это нужно

Обычный `CTE` помогает разложить запрос по шагам. Recursive CTE нужен, когда данные описывают иерархию или цепочку, по которой нужно идти шаг за шагом.

Типичные случаи:

- дерево категорий;
- оргструктура;
- цепочка parent-child;
- граф зависимостей в упрощённом виде.

## Как об этом думать

Recursive CTE работает как цикл внутри SQL:

1. есть базовый шаг — откуда стартуем;
2. есть рекурсивный шаг — как перейти к следующему уровню;
3. запрос повторяет этот переход, пока есть новые строки.

Хороший mental model: recursive CTE позволяет SQL самому пройти по иерархии, а не заставлять приложение делать это снаружи.

## Базовая структура

```sql
WITH RECURSIVE tree AS (
    SELECT id, parent_id, name, 0 AS depth
    FROM categories
    WHERE parent_id IS NULL

    UNION ALL

    SELECT c.id, c.parent_id, c.name, t.depth + 1
    FROM categories AS c
    JOIN tree AS t ON c.parent_id = t.id
)
SELECT *
FROM tree;
```

По смыслу это значит:

- сначала взять корни;
- затем присоединять к ним детей;
- продолжать, пока иерархия не закончится.

## Где ошибаются чаще всего

- не различать базовый и рекурсивный шаг;
- забывать условие, откуда начинается обход;
- создавать цикл в данных и получать бесконечную логику;
- использовать recursive CTE там, где обычного `JOIN` уже достаточно.
