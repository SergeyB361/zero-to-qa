# Финальная advanced SQL practice

## Зачем это нужно
Перед финальным пакетом запросов нужно чётко определить scope: какие вопросы отвечаем, какие таблицы используем, какие артефакты сдаём.

## Ключевые идеи
- scope
- question-driven SQL
- deliverables
- demo flow

## Практический фокус
Не начинай capstone с кода. Сначала зафиксируй список инженерных вопросов и проверок.

## Типичные ошибки
- прыгать в запросы без постановки задачи
- делать capstone как случайный набор SELECT

## Практика
В `practice.sql` реализуй функции:
- `list_capstone_questions` - Верни 3-5 инженерных вопроса для capstone.
- `choose_core_tables` - Верни строку с ядром таблиц capstone.
- `define_output_sections` - Верни строку с секциями итогового отчёта.

## Что дальше
Сначала запусти `examples.sql`, затем доведи функции из `practice.sql` до expected-результатов.
