# EXPLAIN и query plan

## Зачем это нужно
Без плана запроса разговор про performance остаётся гаданием. План показывает, сканируется таблица целиком или используется индекс.

## Ключевые идеи
- EXPLAIN QUERY PLAN
- SCAN
- SEARCH
- индекс в плане

## Практический фокус
Смотри не на “красоту” SQL, а на то, как база собирается его исполнять.

## Типичные ошибки
- судить о производительности только по длине запроса
- не сравнивать план до и после изменения

## Практика
В `practice.sql` реализуй функции:
- `plan_before_index` - Верни текст плана для поиска по endpoint до индекса.
- `plan_after_index` - Создай индекс и верни текст плана после него.
- `compare_plans` - Верни True, если планы до и после отличаются.

## Что дальше
Сначала запусти `examples.sql`, затем доведи функции из `practice.sql` до expected-результатов.
