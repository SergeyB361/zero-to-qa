# Мини-проект: Query Optimization Lab

## Что это за день

Это не набор разрозненных упражнений, а маленькая лаборатория по оптимизации SQL.

Твоя задача — не просто “починить медленный запрос”, а показать инженерный процесс:

1. понять исходную логику;
2. найти проблемное место;
3. предложить изменение;
4. сравнить план до и после;
5. доказать, что результат не изменился.

## Что здесь проверяется

Этот мини-проект проверяет, умеешь ли ты:

- читать query plan;
- выбирать разумный индекс;
- переписывать неудачный запрос;
- объяснять, почему изменение действительно полезно.

## Как правильно проходить

Рабочий порядок такой:

1. сначала прочитай `spec.md`;
2. посмотри на стартовые запросы и исходную схему;
3. зафиксируй проблему для каждого кейса;
4. только потом начинай оптимизировать.

Если сразу бросаться менять SQL, легко потерять контроль над смыслом и получить “быстрый, но неправильный” результат.

## Что должно получиться в конце

По хорошему результату должно быть видно:

- какой запрос был проблемным;
- что именно ты изменил;
- как изменился план;
- почему это изменение можно считать удачным.

## На что обратить внимание

- не добавляй индексы без объяснения сценария;
- не лечи плохой `JOIN` одним `DISTINCT`;
- не меняй бизнес-логику ради красивого плана;
- описывай выводы коротко и предметно.
