# Set operations

## Когда это нужно
Set operations нужны, когда ты хочешь сравнивать и объединять результаты нескольких выборок.

Типовые вопросы:
- кто встречается в двух ролях сразу;
- какие значения есть в одном наборе, но нет в другом;
- как собрать один список из нескольких источников.

## Три основные операции
На базовом уровне нужно уверенно понимать:
- `UNION`
- `UNION ALL`
- `INTERSECT`
- `EXCEPT`

## Как об этом думать
Каждый `SELECT` возвращает набор строк. Set operation берёт два таких набора и строит новый.

Важно:
- количество колонок слева и справа должно совпадать;
- типы колонок должны быть совместимы;
- итоговая сортировка задаётся после всей операции, а не внутри каждого блока.

## Что делает каждая операция
- `UNION` — объединяет результаты и убирает дубликаты.
- `UNION ALL` — объединяет результаты и сохраняет дубликаты.
- `INTERSECT` — оставляет только строки, которые есть в обоих результатах.
- `EXCEPT` — оставляет строки из первого результата, которых нет во втором.

## Когда выбирать UNION и UNION ALL
Если тебе нужен именно набор уникальных значений, используй `UNION`.
Если тебе важно сохранить повторы и увидеть полный поток строк, используй `UNION ALL`.

## Почему это полезно QA и аналитике
Это удобный инструмент для сравнений между ролями, статусами и источниками данных.

Например:
- люди, которые и владеют проектом, и репортят дефекты;
- пользователи, назначенные на задачи, но не являющиеся owner проекта;
- статусы, которые встречаются в одной таблице, но не встречаются в другой.

## Типичные ошибки
- пытаться объединить выборки с разным числом колонок;
- забывать, что `UNION` удаляет дубликаты;
- ожидать сортировку без явного `ORDER BY` после всей операции;
- путать `EXCEPT` с фильтрацией через `WHERE`.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. чем `UNION` отличается от `UNION ALL`;
2. что делает `INTERSECT`;
3. что делает `EXCEPT`;
4. почему структура левой и правой выборки должна совпадать.
