# Транзакции: база

## Когда это нужно
Транзакция нужна там, где несколько изменений должны считаться одной логической операцией. Если один шаг не удался, база не должна остаться в промежуточном состоянии.

Практический смысл простой:
- либо применилось всё;
- либо не применилось ничего.

## Как об этом думать
Транзакция — это защищённый блок команд.

Ты явно говоришь базе:
1. начать блок изменений;
2. выполнить несколько действий;
3. либо подтвердить их через `COMMIT`, либо отменить через `ROLLBACK`.

## Базовый синтаксис
```sql
BEGIN;
UPDATE tasks
SET status = 'closed', closed_at = NOW()
WHERE id = 1;
COMMIT;
```

Если вместо `COMMIT` выполнить `ROLLBACK`, база вернётся к состоянию до `BEGIN`.

## Что делают команды
- `BEGIN` — открывает транзакцию.
- `COMMIT` — подтверждает все изменения внутри транзакции.
- `ROLLBACK` — отменяет все изменения внутри транзакции.

## Безопасный workflow
Для базового уровня удобно мыслить так:
1. проверить текущее состояние через `SELECT`;
2. открыть транзакцию;
3. выполнить изменение;
4. снова проверить `SELECT` внутри транзакции;
5. принять решение: `COMMIT` или `ROLLBACK`.

## Почему это важно в Postgres
В PostgreSQL транзакции — это не дополнительная тема, а базовая часть нормальной работы с данными.

Позже поверх этого появятся:
- уровни изоляции;
- блокировки;
- deadlocks.

Но без понимания `BEGIN / COMMIT / ROLLBACK` эти темы будут висеть в воздухе.

## Типичные ошибки
- менять данные без предварительного `SELECT`;
- забывать, что `COMMIT` делает изменение постоянным;
- думать, что `ROLLBACK` отменяет только последнюю строку;
- тестировать изменяющие запросы прямо на dataset без транзакции.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. зачем нужен `BEGIN`;
2. когда использовать `COMMIT`;
3. когда использовать `ROLLBACK`;
4. как проверить состояние до и после изменения.
