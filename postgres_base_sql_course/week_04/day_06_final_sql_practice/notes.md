# Финальная практика по week 04

## Зачем нужен этот день
На этой неделе ты увидел не просто отдельные конструкции, а набор инструментов, которые часто используются в реальных Postgres-запросах:
- транзакции;
- set operations;
- условные выражения;
- date/time;
- характерные Postgres-паттерны.

Финальная практика нужна, чтобы перестать мыслить ими по отдельности и начать собирать цельные SQL-решения.

## Что считается хорошим решением
Хорошее решение здесь:
- читает задачу как бизнес-вопрос;
- выбирает подходящую конструкцию, а не первую попавшуюся;
- использует alias и порядок блоков так, чтобы запрос можно было читать;
- не делает лишних подзапросов там, где хватает одного понятного SELECT.

## Как подходить к задаче
1. Сначала понять, какой это класс задачи: сравнение наборов, классификация, временная аналитика или Postgres-specific summary.
2. Выбрать ядро запроса.
3. Проверить expected не только по числу строк, но и по смыслу результата.

## Что особенно важно
- не усложнять set operations лишними join'ами;
- при `DISTINCT ON` всегда думать, какая строка должна победить;
- при временных запросах явно контролировать bucket и тип результата;
- при summary-запросах смотреть, нельзя ли решить задачу через `FILTER`.

## Что должно получиться
После этого дня ты должен уверенно решать небольшие аналитические задачи на Postgres, не уходя ни в Python, ни в внешнюю логику поверх базы.
