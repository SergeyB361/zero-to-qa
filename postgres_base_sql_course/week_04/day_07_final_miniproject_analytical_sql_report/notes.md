# Финальный мини-проект: analytical SQL report

## Зачем нужен этот день
Это финальная сборка базового Postgres SQL-трека.

До этого ты проходил конструкции по частям. Здесь задача уже ближе к реальной работе: написать небольшой набор аналитических отчётов по одному dataset и показать, что ты умеешь собирать понятные Postgres-native запросы без Python-обвязки.

## Что считается сильным результатом
Сильный результат здесь — это не максимальное количество запросов, а:
- 4-5 отчётов, каждый из которых отвечает на понятный вопрос;
- читаемый SQL с хорошими alias;
- осмысленное использование тем недели;
- demo flow, который можно запустить на базе `zero_to_qa` и получить понятный вывод.

## Как работать
1. Прочитать `spec.md`.
2. Выделить отдельный блок на каждый отчёт.
3. Подобрать для каждого отчёта правильный инструмент: `FILTER`, `DISTINCT ON`, `CASE`, `STRING_AGG`, date/time grouping или set operations.
4. Добавить короткие комментарии, чтобы файл читался как demo script.

## Чего не делать
- не смешивать в одном запросе сразу все приёмы без причины;
- не писать отчёт, смысл которого нельзя объяснить одной фразой;
- не оставлять сырой SQL без alias и структуры.

## Что должно получиться
Итогом должен стать один Postgres SQL-файл, который можно выполнить по шагам и увидеть компактный набор аналитических отчётов по проектам, задачам, тестовым запускам и дефектам.
