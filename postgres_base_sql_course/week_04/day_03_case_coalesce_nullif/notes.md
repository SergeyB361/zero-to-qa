# CASE, COALESCE, NULLIF

## Когда это нужно
Эти выражения нужны, когда голых значений из таблицы недостаточно и нужно чуть умнее обработать данные прямо в запросе.

Типовые сценарии:
- дать человеку читаемую метку вместо сырого значения;
- подставить запасное значение вместо `NULL`;
- превратить одно конкретное значение в `NULL`.

## CASE
`CASE` позволяет описать условную логику внутри SQL.

Базовая форма:
```sql
CASE
    WHEN status = 'closed' THEN 'done'
    WHEN status = 'blocked' THEN 'risk'
    ELSE 'active'
END
```

Это удобно, когда нужно классифицировать строки по бизнес-смыслу.

## COALESCE
`COALESCE` берёт первый не-`NULL` аргумент.

Пример:
```sql
COALESCE(closed_at::text, 'not closed yet')
```

Это полезно, когда в отчёте нельзя оставлять пустое значение.

## NULLIF
`NULLIF(a, b)` возвращает `NULL`, если `a = b`. Иначе возвращает `a`.

Пример:
```sql
NULLIF(priority, 'high')
```

Если priority = `high`, результатом будет `NULL`.

## Как об этом думать
- `CASE` — это ветвление по правилам.
- `COALESCE` — это запасной вариант для `NULL`.
- `NULLIF` — это способ скрыть одно конкретное значение и заменить его на `NULL`.

## Где это нужно в реальных запросах
- красивый отчёт для человека;
- преобразование статусов в группы риска;
- подготовка данных для агрегаций;
- нормализация сырых данных прямо в SELECT.

## Типичные ошибки
- путать `CASE` с фильтрацией через `WHERE`;
- забывать приводить типы в `COALESCE`, если аргументы разных типов;
- использовать `NULLIF`, не понимая, зачем тебе нужен `NULL` в результате.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. когда использовать `CASE`;
2. что делает `COALESCE`;
3. что делает `NULLIF`;
4. как эти выражения помогают готовить читаемый отчёт.
