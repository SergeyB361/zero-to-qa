# NULL, LIKE, ILIKE, IN, BETWEEN

## Когда это нужно
Почти сразу после простого `=` появляются реальные условия фильтрации:
- значение отсутствует;
- текст совпадает по шаблону;
- значение входит в список;
- значение попадает в диапазон.

Именно для этого нужны `NULL`, `LIKE`, `ILIKE`, `IN`, `BETWEEN`.

## NULL
`NULL` означает не пустую строку и не ноль, а отсутствие значения.

Из-за этого нельзя писать:
```sql
WHERE closed_at = NULL
```

Правильно:
```sql
WHERE closed_at IS NULL
```

Или наоборот:
```sql
WHERE closed_at IS NOT NULL
```

## LIKE и ILIKE
`LIKE` — поиск по шаблону, чувствительный к регистру.
`ILIKE` — Postgres-вариант нечувствительного к регистру поиска.

Пример:
```sql
WHERE title LIKE 'Login%'
WHERE title ILIKE '%login%'
```

Шаблоны:
- `%` — любое количество символов;
- `_` — ровно один символ.

## IN
`IN` нужен, когда допустимых значений несколько.

```sql
WHERE status IN ('open', 'blocked')
```

Это читается лучше, чем длинная цепочка `OR`.

## BETWEEN
`BETWEEN` проверяет попадание в диапазон.

```sql
WHERE duration_seconds BETWEEN 30 AND 50
```

Важно: обе границы включены.

## Как выбирать инструмент
- отсутствует значение -> `IS NULL` / `IS NOT NULL`
- нужно совпадение по шаблону -> `LIKE` или `ILIKE`
- одно из нескольких значений -> `IN`
- диапазон чисел, дат, длительностей -> `BETWEEN`

## Где здесь Postgres-специфика
Главный полезный ранний Postgres-элемент в этой теме — `ILIKE`. В SQLite обычно всё упрощено сильнее, а в Postgres полезно сразу видеть явный case-insensitive поиск.

## Частые ошибки
- писать `= NULL` вместо `IS NULL`;
- забывать `%` в `LIKE`/`ILIKE`;
- не помнить, что `BETWEEN` включает обе границы;
- писать длинный `OR`, когда лучше `IN`.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен различать:
1. отсутствие значения;
2. поиск по шаблону;
3. поиск по списку;
4. поиск по диапазону.
