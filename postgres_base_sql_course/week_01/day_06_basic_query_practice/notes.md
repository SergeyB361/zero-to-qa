# Практика на базовые запросы

## Зачем нужен этот день
До этого темы шли по одной. Но реальные задачи почти никогда не приходят в виде «чистый WHERE без всего остального».

Обычно в одном запросе сразу сочетаются:
- выбор колонок;
- фильтрация;
- сортировка;
- функции;
- ограничение по числу строк.

## Как подходить к задаче
Не пиши весь запрос сразу. Разбивай задачу на части:
1. какая таблица нужна;
2. какие строки должны остаться;
3. какие колонки нужно показать;
4. нужна ли сортировка;
5. нужен ли `LIMIT`;
6. нужна ли функция или alias.

## Как переводить условие в SQL
Если условие говорит:
- «покажи активных пользователей из web-команды» — это фильтр;
- «отсортируй по времени создания» — это `ORDER BY`;
- «покажи только первые 2» — это `LIMIT`;
- «покажи длину названия» — это функция.

То есть сначала разбирается смысл, потом собирается запрос.

## Как себя проверять
После написания запроса спроси себя:
- правильная ли таблица выбрана;
- фильтр буквально соответствует условию;
- сортировка действительно та, что нужна;
- нет ли лишних колонок;
- не потеряна ли часть условия.

## Почему это важнее, чем просто помнить синтаксис
Синтаксис можно подсмотреть. Гораздо важнее уметь:
- прочитать задачу;
- выбрать конструкцию;
- собрать запрос без случайного перебора.
