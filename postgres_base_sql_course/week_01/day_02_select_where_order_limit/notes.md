# SELECT, WHERE, ORDER BY, LIMIT

## Когда это нужно
Это базовый слой чтения данных. Почти любой реальный SQL-запрос начинается с того, что ты:
- выбираешь таблицу;
- отбираешь нужные строки;
- сортируешь результат;
- ограничиваешь выборку.

Если этот уровень не понятен, дальше `JOIN`, подзапросы и агрегации будут выглядеть как набор случайных конструкций.

## Базовый шаблон
```sql
SELECT col1, col2
FROM table_name
WHERE condition
ORDER BY col1 ASC
LIMIT 10;
```

Полезно понимать не только как написать этот шаблон, но и как прочитать его по смыслу.

## Что делает каждая часть
### SELECT
Определяет, какие колонки попадут в результат.

```sql
SELECT id, name
```

Это значит: покажи только `id` и `name`.

### FROM
Показывает, из какой таблицы берутся данные.

```sql
FROM users
```

### WHERE
Оставляет только строки, которые подходят под условие.

В Postgres важно сразу привыкать к реальным типам. Например, для boolean-колонок полезнее писать:
```sql
WHERE is_active IS TRUE
```
а не переносить мышление из SQLite с `1/0`.

### ORDER BY
Сортирует результат.

```sql
ORDER BY name ASC
```

`ASC` — по возрастанию, `DESC` — по убыванию.

### LIMIT
Ограничивает число строк в результате.

```sql
LIMIT 3
```

## Как читать запрос целиком
Пример:
```sql
SELECT id, status, estimate_points
FROM tasks
WHERE status = 'open'
ORDER BY estimate_points DESC
LIMIT 2;
```

По смыслу это значит:
1. взять таблицу `tasks`;
2. оставить только открытые задачи;
3. отсортировать их по `estimate_points` сверху вниз;
4. взять две верхние строки;
5. показать только `id`, `status`, `estimate_points`.

## Как переводить условие задачи в SQL
Если задача говорит:
- «покажи активных пользователей» — нужен `WHERE is_active IS TRUE`;
- «отсортируй по времени создания» — нужен `ORDER BY created_at`;
- «возьми только первые 5» — нужен `LIMIT 5`.

То есть запрос лучше строить от смысла, а не пытаться вспомнить формулу целиком.

## Почему порядок важен
`LIMIT` без `ORDER BY` часто даёт просто первые попавшиеся строки, а не «самые нужные».

Поэтому:
- `ORDER BY created_at DESC LIMIT 3` — это последние 3 записи;
- `LIMIT 3` без сортировки — это просто 3 строки в неопределённом порядке.

## Частые ошибки
- использовать `SELECT *`, когда нужны 1-2 колонки;
- писать `WHERE is_active = 1` вместо работы с boolean как с boolean;
- сортировать не по тому полю;
- использовать `LIMIT`, не понимая, как упорядочены строки.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. что делает каждая часть `SELECT`, `FROM`, `WHERE`, `ORDER BY`, `LIMIT`;
2. как прочитать запрос обычным языком;
3. почему `LIMIT` без сортировки часто даёт бесполезный результат.
