# DISTINCT, aliases, базовые функции

## Когда это нужно
На этом этапе запросы становятся не просто рабочими, а читаемыми и удобными.

Эти инструменты нужны, чтобы:
- убрать дубликаты;
- сделать результат понятнее по именам колонок;
- выполнить простое преобразование прямо в SQL.

## DISTINCT
`DISTINCT` убирает повторяющиеся строки результата по выбранным колонкам.

```sql
SELECT DISTINCT team
FROM users;
```

Это значит: показать уникальные значения `team`, а не все строки пользователей.

## Aliases
Alias — временное имя колонки или таблицы внутри запроса.

Для колонки:
```sql
SELECT name AS user_name, team AS squad
FROM users;
```

Для таблицы:
```sql
FROM tasks AS t
```

Aliases нужны не для красоты, а чтобы результат и сам запрос было проще читать.

## Базовые функции
На этом дне полезно привыкнуть к простым функциям уровня:
- `UPPER()`
- `LOWER()`
- `LENGTH()`
- `COALESCE()` как раннее знакомство с заменой `NULL`

Пример:
```sql
SELECT title, LENGTH(title) AS title_len
FROM test_cases;
```

## Где здесь Postgres
В Postgres сразу нормально работают строковые функции, работа с timestamp и приведение типов. Пока не нужно уходить глубоко, но полезно видеть, что база умеет немного преобразовывать результат прямо в запросе.

## Частые ошибки
- использовать `DISTINCT`, не понимая, откуда взялись дубликаты;
- давать alias, которые ничего не объясняют;
- забывать, что функция применяется к колонке или выражению;
- использовать `SELECT *`, а потом удивляться, что результат трудно читать.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. чем `DISTINCT` отличается от обычного `SELECT`;
2. зачем нужен `AS`;
3. когда функцию удобно вызвать прямо в SQL.
