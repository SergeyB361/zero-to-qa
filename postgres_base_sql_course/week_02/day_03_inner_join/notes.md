# INNER JOIN

## Когда это нужно
`INNER JOIN` нужен, когда данные лежат в разных таблицах, но логически относятся к одному объекту: задача и исполнитель, проект и владелец, запуск теста и тест-кейс.

## Как думать о JOIN
`JOIN` — это не магическое склеивание всего со всем. Это способ сказать базе: возьми строки из двух таблиц и сопоставь их по правилу связи.

Обычно правило связи выглядит так:
```sql
ON tasks.assignee_id = users.id
```

## Что делает `INNER JOIN`
`INNER JOIN` оставляет только те строки, для которых пара нашлась с обеих сторон.

Если у задачи нет подходящего пользователя, такая задача в результате не появится.

## Почему alias почти обязательны
После `JOIN` имена таблиц быстро становятся длинными и шумными. Alias вроде `t`, `u`, `p` делают запрос читаемым.

## Где это нужно QA
- получить имя пользователя для задачи;
- понять, к какому проекту относится задача;
- связать `test_runs` и `test_cases`;
- проверить целостность связей между таблицами.

## Частые ошибки
- соединять таблицы не по тем колонкам;
- забывать условие `ON`;
- не понимать, что `INNER JOIN` выбрасывает строки без пары;
- путаться в одинаковых колонках `id`, `status`, `name`.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. по каким колонкам строится связь;
2. почему `INNER JOIN` не показывает строку без совпадения;
3. зачем alias нужны не для красоты, а для ясности.
