# Практика на JOIN и агрегации

## Зачем нужен этот день
До этого `JOIN` и агрегации шли по отдельности. Но реальные отчёты почти всегда комбинируют их вместе:
- сначала связать таблицы;
- потом сгруппировать результат;
- затем посчитать агрегаты.

## Как подходить к задаче
Разбивай запрос на три шага:
1. какие таблицы нужно соединить;
2. какая строка является единицей анализа;
3. по какому полю группировать и какой агрегат считать.

## Пример мышления
Если задача звучит как «средняя длительность по test case», то логика такая:
- стартуем с `test_runs`;
- соединяем `test_cases`, чтобы получить title;
- группируем по `test_cases.title`;
- считаем `AVG(duration_seconds)`.

## Частые ошибки
- пытаться сначала сгруппировать, а потом думать о join;
- не понимать, какая таблица является основной;
- добавлять в `SELECT` колонку, которая не попала в `GROUP BY` и не агрегирована.

## Что нужно понимать перед практикой
После этого дня ты должен уметь строить короткие отчёты по нескольким таблицам, а не только по одной.
