# GROUP BY и HAVING

## Когда это нужно
Как только появляется вопрос уровня «сколько по каждому статусу» или «среднее по каждой группе», одного агрегата уже мало. Нужно не просто посчитать выборку целиком, а разбить данные на группы и посчитать агрегат внутри каждой группы.

Для этого нужны `GROUP BY` и `HAVING`.

## Как об этом думать
Агрегат без группировки отвечает на вопрос про весь набор строк.
`GROUP BY` разбивает строки на группы, а агрегат считается отдельно для каждой группы.

Пример:
```sql
SELECT status, COUNT(*)
FROM test_runs
GROUP BY status;
```

Это уже не один итог по всей таблице, а один итог на каждый `status`.

## Что делает `GROUP BY`
`GROUP BY` говорит базе: собери вместе строки с одинаковым значением указанной колонки или набора колонок.

После этого агрегаты считаются внутри группы.

## Что делает `HAVING`
`HAVING` фильтрует уже готовые группы.

Это важно отличать от `WHERE`:
- `WHERE` фильтрует строки до группировки;
- `HAVING` фильтрует группы после группировки.

Пример:
```sql
SELECT status, COUNT(*) AS total
FROM test_runs
GROUP BY status
HAVING COUNT(*) >= 2;
```

## Как читать запрос по смыслу
1. берутся строки из таблицы;
2. `WHERE` при необходимости отбрасывает лишние строки;
3. `GROUP BY` делит оставшиеся строки на группы;
4. агрегаты считаются внутри групп;
5. `HAVING` оставляет только нужные группы.

## Частые ошибки
- писать в `SELECT` колонку, которая не попала в `GROUP BY` и не обёрнута в агрегат;
- путать `WHERE` и `HAVING`;
- ожидать, что `GROUP BY` сохранит детальные строки, а не свёрнутый результат.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. зачем нужен `GROUP BY`;
2. чем `HAVING` отличается от `WHERE`;
3. почему после группировки результат уже не про отдельные строки, а про группы.
