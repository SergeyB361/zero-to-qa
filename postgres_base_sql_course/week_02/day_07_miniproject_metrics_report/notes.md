# Мини-проект: metrics report

## Зачем нужен этот день
На неделе уже были:
- агрегаты;
- группировки;
- `INNER JOIN` и `LEFT JOIN`;
- multi-join patterns.

В мини-проекте нужно собрать это в один короткий SQL-report, который выглядит как нормальный инженерный артефакт, а не как набор несвязанных запросов.

## Что считается сильным результатом
Сильный результат здесь — это:
- один SQL-файл с несколькими отчётами;
- хорошие alias;
- понятные группы и метрики;
- отсутствие лишнего шума в запросах.

## Как работать
1. Прочитать `spec.md`.
2. Для каждого отчёта понять единицу анализа.
3. Выбрать таблицы и связи.
4. Решить, нужен `INNER JOIN` или `LEFT JOIN`.
5. Выбрать группировку и агрегат.

## Что не нужно усложнять
- не нужно строить огромный один запрос, если лучше сделать несколько отдельных отчётов;
- не нужно тащить все колонки, если нужны 2-3;
- не нужно добавлять подзапросы, если задача решается обычным `JOIN + GROUP BY`.

## Что должно получиться
Итогом должен стать читаемый SQL-файл, который показывает несколько метрик по QA dataset и демонстрирует, что ты умеешь строить базовые аналитические отчёты на Postgres.
