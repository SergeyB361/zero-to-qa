# Postgres types и identity columns

## Когда это нужно
На этом этапе полезно понять, что типы данных — это не второстепенная деталь. Они определяют, какие значения допустимы, как база их хранит и как работает часть функций и сравнений.

## Базовые типы, которые нужны сразу
Для этого курса достаточно уверенно понимать:
- `TEXT`
- `INTEGER` / `BIGINT`
- `BOOLEAN`
- `NUMERIC`
- `DATE`
- `TIMESTAMPTZ`

## Как об этом думать
Тип колонки — это часть контракта данных.

Если колонка — `BOOLEAN`, база ожидает логическое значение.
Если колонка — `TIMESTAMPTZ`, база хранит момент времени с timezone.
Если колонка — `NUMERIC`, ты явно говоришь, что нужна точная числовая модель, а не просто «какое-то число».

## Identity columns
В новом Postgres-курсе id по умолчанию лучше создавать через:
```sql
BIGINT GENERATED BY DEFAULT AS IDENTITY
```

Это современный Postgres-native способ автоматически генерировать значения id.

## Почему это лучше, чем ручной id
- меньше ручной работы;
- меньше риск конфликтов id;
- схема сразу описывает, что id генерируется базой.

## Приведение типов
Иногда в SQL нужно явно привести тип:
```sql
closed_at::text
```

Это полезно, когда ты хочешь вывести timestamp как текст или совместить типы в функции вроде `COALESCE`.

## Частые ошибки
- выбирать слишком общий тип без смысла;
- не понимать разницу между `DATE` и `TIMESTAMPTZ`;
- вставлять id руками, хотя колонка identity может сгенерировать его сама;
- игнорировать приведение типов, когда база его требует явно.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. зачем типы выбираются осознанно;
2. что такое identity column в Postgres;
3. когда нужно явное приведение типа.
