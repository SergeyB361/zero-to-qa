# EXISTS / NOT EXISTS

## Когда это нужно
`EXISTS` нужен, когда вопрос звучит не «какие значения вернуть», а «есть ли вообще связанная строка».

Это особенно полезно для проверок существования и отсутствия связи:
- есть ли у пользователя проекты;
- есть ли у задачи дефекты;
- есть ли у test case failed run;
- есть ли у проекта задачи без дефектов.

## Как об этом думать
`EXISTS` не тащит набор значений наружу. Он отвечает только на один вопрос: внутренний запрос нашёл хотя бы одну строку или нет.

Поэтому `EXISTS` хорошо подходит для semi-join логики: оставить строку, если подходящая запись существует.

## Базовый шаблон
```sql
SELECT u.id, u.name
FROM users AS u
WHERE EXISTS (
    SELECT 1
    FROM projects AS p
    WHERE p.owner_id = u.id
);
```

Смысл:
- берём строку пользователя;
- проверяем, существует ли хотя бы один проект, где он owner;
- если да, строка пользователя остаётся.

## NOT EXISTS
`NOT EXISTS` — зеркальный вариант: оставить строку, только если подходящая запись не найдена.

Это удобный способ искать «сиротские» или отсутствующие связи.

## Почему EXISTS часто удобнее, чем IN
Если условие зависит от внешней строки, `EXISTS` обычно читается лучше и легче выражает смысл.

Например, «есть ли у этого пользователя хотя бы одна задача» — это естественный вопрос для `EXISTS`.

## Частые ошибки
- не понимать, что внутренний запрос связан с внешней строкой;
- писать `EXISTS`, но не задавать правильное условие связи;
- использовать `NOT EXISTS`, не проверив, что именно означает отсутствие строки.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. чем `EXISTS` отличается от подзапроса со списком значений;
2. почему `NOT EXISTS` удобен для поиска отсутствующих связей;
3. как читать correlated subquery по шагам.
