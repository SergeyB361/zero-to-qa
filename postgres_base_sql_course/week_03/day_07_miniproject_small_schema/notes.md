# Мини-проект: small schema

## Зачем нужен этот день
На этой неделе фокус сместился с готового dataset на саму схему: DDL, ключи, ограничения, типы и запросы поверх собственной модели.

Мини-проект нужен, чтобы собрать это в один маленький, но цельный SQL-артефакт.

## Что считается сильным результатом
Сильный результат здесь — это не огромная схема, а:
- 2-3 таблицы, которые реально связаны;
- хорошие типы данных;
- осмысленные constraints;
- seed-данные;
- 1-2 проверочных запроса, которые показывают, что схема работает.

## Как работать
1. Прочитать `spec.md`.
2. Нарисовать схему словами: какие сущности и как связаны.
3. Написать `CREATE TABLE` с типами и ограничениями.
4. Добавить seed-данные.
5. Добавить короткий demo flow.

## Чего не делать
- не раздувать схему ради количества таблиц;
- не оставлять типы «наугад»;
- не писать DDL без ограничений, если они очевидны по смыслу.

## Что должно получиться
Итогом должен стать Postgres-native SQL-файл, который создаёт маленькую схему, заполняет её и показывает короткий рабочий запрос поверх этой схемы.
