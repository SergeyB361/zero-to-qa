# Мини-проект: optimization lab

## Зачем нужен этот день
Это финальная сборка performance-недели.

Здесь уже мало просто написать правильный SQL. Нужно показать, что ты умеешь:
- увидеть performance-вопрос;
- показать plan;
- предложить rewrite или индекс;
- объяснить эффект на языке SQL и execution plan.

## Что считается сильным результатом
Сильный результат — это не “насыпал индексов”, а:
- 3-4 понятных кейса;
- у каждого кейса есть baseline-запрос;
- есть улучшенная версия;
- есть объяснение, почему rewrite или индекс имеет смысл.

## Как работать
1. Выбрать несколько representative запросов.
2. Для каждого показать исходный вариант.
3. Добавить `EXPLAIN` или `EXPLAIN ANALYZE`.
4. Добавить rewrite или индекс.
5. Зафиксировать итоговый вывод по кейсу.

## Чего не делать
- не превращать проект в хаотичный набор запросов;
- не писать “стало быстрее” без плана;
- не менять несколько вещей сразу, если потом нельзя объяснить эффект.

## Что должно получиться
Итогом должен стать SQL-файл, который можно запускать как лабораторную работу по performance-разбору в Postgres.
