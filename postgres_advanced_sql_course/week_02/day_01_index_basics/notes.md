# Index basics

## Когда это нужно
Индексы нужны не для красоты схемы, а для того, чтобы база не искала нужные строки полным перебором каждый раз.

Типовые вопросы:
- почему запрос по одной колонке внезапно медленный;
- почему lookup по статусу или внешнему ключу не масштабируется;
- почему один и тот же SQL на маленьком наборе данных кажется нормальным, а на большом начинает деградировать.

## Как об этом думать
Индекс — это дополнительная структура данных, которая помогает найти строки быстрее.

Но это всегда компромисс:
- чтение часто выигрывает;
- запись становится чуть дороже;
- индекс занимает место.

## Что важно понять сразу
Индекс не ускоряет всё подряд. Он полезен там, где:
- есть поиск по условию;
- есть join по ключу;
- есть сортировка или фильтрация по повторяющимся паттернам доступа.

## Базовый синтаксис
```sql
CREATE INDEX idx_tasks_status ON tasks(status);
```

Это значит: создать индекс по колонке `status` в таблице `tasks`.

## Где индексы особенно полезны
- `WHERE status = ...`
- `WHERE project_id = ...`
- `JOIN ... ON t.project_id = p.id`
- частые фильтры по времени и foreign key

## Чего индекс не гарантирует
Сам факт существования индекса не означает, что Postgres его использует.

Планировщик смотрит на:
- размер таблицы;
- селективность условия;
- стоимость чтения;
- статистику.

Поэтому говорить об индексе без `EXPLAIN` — неполноценно.

## Типичные ошибки
- создавать индекс на каждую колонку подряд;
- не понимать цену индексов для `INSERT/UPDATE/DELETE`;
- думать, что индекс обязательно будет использован;
- не различать полезный индекс и шумовой индекс.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. зачем нужен индекс;
2. где индекс потенциально помогает;
3. почему использование индекса проверяется через план, а не через догадки.
