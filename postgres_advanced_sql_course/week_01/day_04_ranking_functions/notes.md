# Ranking functions

## Когда это нужно
Ranking functions нужны, когда строки внутри группы нужно упорядочить и присвоить им место.

Типовые вопросы:
- какой run у пользователя был последним;
- какая задача самая большая по estimate_points;
- кто в топе по длительности, а кто ниже;
- как выбрать одну лучшую строку на группу через ranking + фильтрацию.

## Три основные функции
- `ROW_NUMBER()`
- `RANK()`
- `DENSE_RANK()`

## Как об этом думать
Все три функции отвечают на вопрос «какое место у строки в упорядоченном наборе», но делают это по-разному.

- `ROW_NUMBER()` — даёт уникальный номер каждой строке.
- `RANK()` — одинаковые значения получают одинаковый ранг, но с пропусками.
- `DENSE_RANK()` — одинаковые значения получают одинаковый ранг, но без пропусков.

## Базовый синтаксис
```sql
ROW_NUMBER() OVER (ORDER BY executed_at DESC)
RANK() OVER (ORDER BY estimate_points DESC)
DENSE_RANK() OVER (ORDER BY estimate_points DESC)
```

## Где это особенно полезно
Очень частый паттерн в Postgres:
1. посчитать `ROW_NUMBER()` по группе;
2. завернуть это в CTE;
3. оставить `WHERE rn = 1`.

Так получают «последний run по пользователю», «самую дорогую задачу по проекту» и похожие выборки.

## Типичные ошибки
- путать `RANK()` и `DENSE_RANK()`;
- забывать, что смысл ranking полностью зависит от `ORDER BY` внутри окна;
- использовать global ranking там, где нужен ranking по группе через `PARTITION BY`.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. чем `ROW_NUMBER()` отличается от `RANK()`;
2. чем `RANK()` отличается от `DENSE_RANK()`;
3. как использовать ranking внутри CTE для выбора top-строк.
