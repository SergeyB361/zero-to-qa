# Window functions

## Когда это нужно
Window functions нужны, когда тебе нужно видеть и отдельную строку, и агрегированный контекст вокруг неё одновременно.

Типовые вопросы:
- сколько всего строк в наборе;
- какая средняя длительность по исполнителю, но на каждой строке run;
- сколько всего points у проекта, но рядом с каждой задачей;
- сколько defects у reporter, но без отдельного GROUP BY-результата.

## Как об этом думать
Обычный `GROUP BY` схлопывает несколько строк в одну.
Window function считает агрегат, но не теряет исходные строки.

Именно поэтому окна удобны для аналитики: ты видишь деталь и summary в одном результате.

## Базовый синтаксис
```sql
COUNT(*) OVER ()
AVG(duration_seconds) OVER (PARTITION BY executed_by)
```

## Что такое OVER
`OVER` говорит Postgres: вычисли функцию не по всей таблице как один итог, а как окно вокруг текущей строки.

## Что делает PARTITION BY
`PARTITION BY` делит строки на группы внутри окна.

Пример:
```sql
AVG(duration_seconds) OVER (PARTITION BY executed_by)
```

Это значит: среднее по каждому исполнителю, но значение будет показано на каждой его строке.

## Почему это важно
Window functions — один из главных инструментов реальной аналитики в SQL.

Без них запросы быстро превращаются в неудобные подзапросы, где приходится постоянно терять строковый контекст и собирать его обратно join'ами.

## Типичные ошибки
- путать window function и `GROUP BY`;
- не понимать, что окно не удаляет строки;
- ставить `PARTITION BY`, не понимая, по какому бизнес-смыслу должна идти группировка.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. зачем нужен `OVER`;
2. чем окно отличается от `GROUP BY`;
3. что делает `PARTITION BY`.
