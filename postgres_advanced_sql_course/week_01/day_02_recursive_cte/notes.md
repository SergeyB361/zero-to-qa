# Recursive CTE

## Когда это нужно
Recursive CTE нужны там, где результат строится шаг за шагом из предыдущего результата.

Типовые сценарии:
- сгенерировать последовательность чисел или дат;
- пройти иерархию;
- строить календарь для time-series отчёта;
- обходить цепочки зависимостей.

## Как об этом думать
Recursive CTE состоит из двух частей:
1. anchor — стартовое состояние;
2. recursive step — правило, как получить следующую строку из предыдущей.

Запрос повторяет recursive step, пока условие не перестанет выполняться.

## Базовый синтаксис
```sql
WITH RECURSIVE numbers AS (
    SELECT 1 AS n
    UNION ALL
    SELECT n + 1
    FROM numbers
    WHERE n < 5
)
SELECT n
FROM numbers;
```

## Где это реально полезно
В этом курсе самый практичный сценарий — календарь для отчёта.

Например, если у тебя есть события только за один день, recursive CTE помогает всё равно построить диапазон дат и показать нули там, где событий не было.

## Почему не всегда нужен recursion
Если задача решается обычным CTE или `generate_series`, recursion не обязателен. Но понять recursive CTE всё равно важно: это базовый инструмент для более сложных запросов и обходов иерархий.

## Типичные ошибки
- забыть anchor-часть;
- сделать условие рекурсии бесконечным;
- не контролировать, как и когда цепочка должна остановиться;
- писать recursion там, где вопрос решается обычным `WITH`.

Перед `practice.sql` ты должен понимать:
1. что такое anchor;
2. что такое recursive step;
3. как recursion останавливается;
4. как использовать recursive CTE для календаря.
