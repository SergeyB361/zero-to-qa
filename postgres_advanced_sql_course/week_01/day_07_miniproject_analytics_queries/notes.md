# Мини-проект: analytics queries

## Зачем нужен этот день
Это финальная сборка первой недели продвинутого Postgres SQL.

До этого ты видел отдельные advanced-инструменты. Теперь задача — собрать небольшой, но цельный пакет аналитических запросов, где уже используются:
- CTE;
- recursive CTE;
- window functions;
- ranking или соседние значения.

## Что считается сильным результатом
Сильный результат здесь — это не максимальное количество хитрых функций, а:
- 4-5 запросов с понятной целью;
- читаемый SQL;
- аккуратные alias;
- использование advanced-инструментов там, где они действительно уместны.

## Как работать
1. Прочитать `spec.md`.
2. Для каждого отчёта сформулировать бизнес-вопрос одной фразой.
3. Выбрать правильный инструмент под каждый отчёт.
4. Собрать всё в один демонстрационный SQL-файл.

## Чего не делать
- не усложнять запросы без выгоды;
- не писать одинаковые подзапросы по нескольку раз, если они естественно выносятся в CTE;
- не терять читаемость ради «advanced-эффекта».

## Что должно получиться
Итогом должен стать SQL-файл, который показывает, что ты умеешь писать уже не только базовые SELECT/JOINS, а компактные аналитические Postgres-запросы с несколькими слоями логики.
