# LEAD, LAG и running totals

## Когда это нужно
Эти функции нужны, когда важна не только текущая строка, но и её связь с соседними строками по времени или порядку.

Типовые вопросы:
- что было перед текущим событием;
- что будет следующим событием;
- сколько накопилось к текущему моменту;
- насколько текущее значение отличается от предыдущего.

## Что делает LAG
`LAG` берёт значение из предыдущей строки внутри окна.

Пример:
```sql
LAG(duration_seconds) OVER (ORDER BY executed_at)
```

## Что делает LEAD
`LEAD` берёт значение из следующей строки.

Пример:
```sql
LEAD(status) OVER (ORDER BY executed_at)
```

## Running total
Running total — это накопительная сумма по порядку.

Пример:
```sql
SUM(duration_seconds) OVER (
    ORDER BY executed_at
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
```

## Как об этом думать
- `LAG` — посмотреть назад.
- `LEAD` — посмотреть вперёд.
- running total — накопить результат шаг за шагом.

Это очень полезно для таймлайнов, метрик и анализа событийных потоков.

## Где это реально применяется
- последовательность test runs;
- анализ времени между событиями;
- накопительная статистика;
- поиск резких скачков между соседними значениями.

## Типичные ошибки
- не задавать `ORDER BY` внутри окна;
- забывать, что первая строка для `LAG` и последняя для `LEAD` обычно дают `NULL`;
- писать running total без явного оконного frame, если нужен именно накопительный результат.
