# CTE basics

## Когда это нужно
CTE (`WITH`) нужны, когда запрос становится длиннее одной прямой выборки и его нужно разбить на читаемые шаги.

Типовые сценарии:
- сначала подготовить промежуточный набор строк;
- затем агрегировать его;
- затем присоединить результат к основной таблице;
- затем использовать этот промежуточный слой ещё раз ниже по запросу.

## Как об этом думать
CTE — это именованный временный результат внутри одного SQL-запроса.

Ты как будто говоришь Postgres:
1. сначала собери этот поднабор;
2. дай ему имя;
3. потом используй его как обычную таблицу в основном SELECT.

## Базовый синтаксис
```sql
WITH unfinished_tasks AS (
    SELECT *
    FROM tasks
    WHERE status <> 'closed'
)
SELECT id, status
FROM unfinished_tasks;
```

## Почему это удобнее, чем длинный вложенный запрос
CTE полезны не потому, что они «магически быстрее», а потому, что они:
- делают запрос читаемым;
- позволяют разбить задачу на смысловые шаги;
- уменьшают вероятность ошибиться в join/aggregate логике.

## Когда CTE особенно уместен
- когда у тебя 2-3 смысловых этапа в одном запросе;
- когда промежуточный результат хочется назвать словами;
- когда нужно сначала агрегировать, а потом снова join'ить.

## Что CTE не делает сам по себе
CTE не гарантирует ускорение. Это прежде всего инструмент структуры и читаемости.

Если запрос медленный, проблема чаще в плане выполнения, индексах или объёме данных, а не в факте использования `WITH`.

## Типичные ошибки
- использовать CTE для тривиального запроса, где он только раздувает текст;
- давать CTE неинформативные имена вроде `tmp1`;
- забывать, что следующий блок видит только то, что явно выбрано в CTE;
- путать CTE с временной таблицей в базе.

## Что нужно понимать перед практикой
Перед `practice.sql` ты должен понимать:
1. зачем нужен `WITH`;
2. как назвать промежуточный результат по смыслу;
3. как использовать CTE в следующем SELECT.
