# Композитные SQL-запросы

## Когда это нужно
После базовых тем важно научиться собирать несколько конструкций в одном запросе. В реальной работе задачи почти никогда не ограничиваются одной идеей вроде "только WHERE" или "только JOIN".

Обычно приходится сочетать:
- выбор нужных колонок;
- `JOIN`;
- фильтрацию;
- агрегаты;
- сортировку.

## Как думать о составном запросе
Хороший составной запрос строится слоями:

1. выбрать базовую таблицу;
2. добавить нужные связи;
3. отфильтровать строки;
4. посчитать агрегаты или вычисления;
5. отсортировать финальный результат.

Если пытаться писать всё сразу одним куском без плана, запрос быстро становится нечитаемым.

## Пример разбиения задачи
Допустим, задача звучит так:
"Показать по каждой команде количество open-задач и суммарную оценку часов."

Как её разложить:
- базовая таблица: `tasks`;
- нужно узнать команду исполнителя -> нужен `JOIN users`;
- нужны только open-задачи -> нужен `WHERE t.status = 'open'`;
- нужно посчитать количество и сумму -> нужны `COUNT(*)` и `SUM(...)`;
- результат нужно отсортировать -> нужен `ORDER BY`.

## Почему порядок сборки важен
Если ты сначала понимаешь смысл задачи, а потом по слоям добавляешь SQL-конструкции, запрос остаётся управляемым.

Если же писать его как одну длинную строку "по памяти", очень легко:
- забыть нужный фильтр;
- посчитать агрегат не по той выборке;
- перепутать уровень группировки;
- потерять читаемость.

## Как проверять такой запрос
Полезный workflow:
1. сначала проверить базовую выборку без агрегаций;
2. потом убедиться, что `JOIN` даёт нужные строки;
3. только потом добавлять `GROUP BY`, `COUNT`, `SUM` и сортировку.

Так проще понять, на каком шаге запрос начал искажать результат.

## Где это нужно QA
Такие запросы полезны для:
- сводок по задачам и проектам;
- аналитики по тестовым запускам;
- коротких SQL-отчётов по данным;
- ручной проверки логики без Python-слоя.

## Частые ошибки
- пытаться решить задачу одним длинным запросом без промежуточной логики;
- агрегировать раньше, чем проверены строки после `JOIN`;
- не понимать, почему нужен именно этот `GROUP BY`;
- сортировать по колонке, которой уже нет в итоговом наборе.

## Что проверить перед практикой
Перед `practice.sql` ты должен понимать:
1. как разложить сложную задачу на SQL-слои;
2. как сочетать `JOIN`, `WHERE`, агрегаты и `ORDER BY`;
3. почему составной запрос лучше собирать по шагам, а не писать вслепую.
