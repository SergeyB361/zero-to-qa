# Подготовка и очистка тестовых данных

## Зачем это нужно
Автотесты часто требуют создать данные перед сценарием и гарантированно удалить их после. Это снижает flaky-поведение и облегчает повторный запуск.

## Что нужно понять
- setup data
- cleanup
- repeatability
- изолированные тесты

## Рабочая логика
1. Определи, из каких таблиц ты читаешь данные.
2. Сузь выборку фильтрами.
3. Только потом добавляй сортировку, группировку или join.
4. Проверяй вывод на маленьком наборе данных.

## Примеры
### Пример 1 - Создать временный test_case
```sql
INSERT INTO test_cases (id, title, area, priority) VALUES (10, 'Temp case', 'sandbox', 'low');
```

### Пример 2 - Проверить, что временная запись появилась
```sql
SELECT COUNT(*) FROM test_cases WHERE id = 10;
```

### Пример 3 - Удалить временную запись
```sql
DELETE FROM test_cases WHERE id = 10;
```

## Типичные ошибки
- оставлять мусор в БД
- генерировать конфликтующие id
- не проверять cleanup

## Практика
В `practice.py` есть функции для самостоятельной реализации:
- `create_temp_case_and_count` - Добавь временный test_case и верни count строк с id = 10.
- `cleanup_temp_case` - Удали test_case с id = 10 и верни count строк после удаления.
- `reset_temp_defect` - Добавь и затем удали временный дефект. Верни итоговое количество таких строк.

## Что дальше
Сначала запусти `examples.py`, затем реализуй функции из `practice.py` и сверь вывод с expected.
