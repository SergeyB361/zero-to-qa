# Транзакции: база

## Когда это нужно
Транзакции нужны там, где несколько изменений должны считаться одной логической операцией. Если одно действие не завершилось полностью, база не должна остаться в поломанном промежуточном состоянии.

Типичный смысл транзакции такой:
- либо применилось всё;
- либо не применилось ничего.

## Базовая идея транзакции
Транзакция - это защищённый блок SQL-операций.

На базовом уровне тебе достаточно помнить три команды:
- `BEGIN` - начать транзакцию;
- `COMMIT` - подтвердить изменения;
- `ROLLBACK` - откатить изменения.

## Как это выглядит по шагам
Самый простой сценарий:

```sql
BEGIN;
UPDATE tasks
SET status = 'closed'
WHERE id = 3;
COMMIT;
```

Как это читать:
1. открыть транзакцию;
2. выполнить изменение;
3. зафиксировать результат как новое состояние базы.

Если вместо `COMMIT` сделать `ROLLBACK`, изменение не сохранится:

```sql
BEGIN;
UPDATE defects
SET status = 'closed'
WHERE id = 1;
ROLLBACK;
```

## Что делает COMMIT
`COMMIT` говорит базе: все изменения внутри транзакции корректны, можно принять их окончательно.

После `COMMIT`:
- новое состояние считается сохранённым;
- последующий `SELECT` уже видит изменённые данные;
- откатить этот шаг командой `ROLLBACK` уже нельзя.

## Что делает ROLLBACK
`ROLLBACK` говорит: этот блок изменений не должен считаться успешным, верни базу к состоянию до `BEGIN`.

Это особенно важно, если внутри транзакции было несколько шагов и один из них оказался неверным.

## Почему это важно для целостности
Представь цепочку:
- создали заказ;
- списали деньги;
- обновили статус.

Если второй шаг сломался, оставлять первый шаг в базе часто нельзя. Иначе система будет хранить неполное, противоречивое состояние.

Именно для таких случаев транзакции и существуют.

## Как проверять эффект транзакции
Нормальный workflow такой:

1. до изменения посмотреть текущее состояние через `SELECT`;
2. выполнить транзакцию;
3. снова сделать `SELECT` и убедиться, что после `COMMIT` данные изменились;
4. отдельно проверить сценарий с `ROLLBACK` и убедиться, что данные не поменялись.

Пример:
```sql
SELECT id, status
FROM tasks
WHERE id = 3;
```

```sql
BEGIN;
UPDATE tasks
SET status = 'closed'
WHERE id = 3;
COMMIT;
```

```sql
SELECT id, status
FROM tasks
WHERE id = 3;
```

## Что важно понять на базовом уровне
Для этого курса не нужно уходить в изоляцию транзакций и блокировки. Сейчас важно понять только фундамент:
- транзакция объединяет несколько операций в один смысловой блок;
- `COMMIT` подтверждает изменения;
- `ROLLBACK` отменяет изменения внутри блока.

## Почему это важно QA
Даже если ты не проектируешь транзакции сам, ты должен понимать:
- почему частично сохранённые данные - это баг;
- как проверять сценарии с ошибками;
- почему после сбоя база должна возвращаться в согласованное состояние.

## Частые ошибки
- думать, что каждая SQL-операция всегда независима;
- не проверять состояние до и после транзакции;
- путать `ROLLBACK` с обычной отменой одной строки;
- не понимать, что транзакция защищает именно группу изменений.

## Что проверить перед практикой
Перед `practice.sql` ты должен понимать:
1. зачем нужен `BEGIN`;
2. что делает `COMMIT`;
3. что делает `ROLLBACK`;
4. как проверить руками, сохранилось изменение или нет.
