# SQLite в Python

## Зачем это нужно
До этого ты писал SQL как отдельный язык. Теперь важно увидеть, как SQL реально используется внутри Python-кода: открыть соединение, выполнить запрос, получить данные, закрыть ресурсы.

## Как об этом думать
Есть два слоя:
- Python управляет процессом работы;
- SQLite исполняет SQL-запросы.

Python не заменяет SQL. Он просто даёт способ запускать SQL из программы и работать с результатом.

## Базовый рабочий поток
Обычно последовательность такая:
1. открыть соединение с базой;
2. создать cursor или использовать connection;
3. выполнить SQL;
4. прочитать результат;
5. при изменении данных сделать `commit()`;
6. закрыть соединение.

Это и есть минимальная модель работы с БД из Python.

## Что важно понять про `commit`
`SELECT` обычно не меняет данные.
`INSERT`, `UPDATE`, `DELETE` меняют. Пока ты не сделал `commit()`, эти изменения могут не считаться окончательно сохранёнными.

Это принципиально важно для тестов и утилит: без `commit()` ты легко получишь "запрос отработал, а данных как будто нет".

## Как читать результат в Python
SQL возвращает табличную выборку. В Python она обычно приходит как список кортежей или отдельных строк результата.

То есть после SQL нужно ещё уметь интерпретировать результат в коде:
- одна строка или много;
- одно значение или несколько колонок;
- нужно ли преобразование в удобный формат.

## Где это нужно QA
Это основа для:
- DB-checks в автотестах;
- подготовки тестовых данных;
- cleanup после тестов;
- служебных утилит для анализа данных.

## Частые ошибки
- забывать `commit()` после изменения данных;
- не закрывать соединение;
- смешивать SQL-логику и Python-логику так, что трудно понять, где ошибка;
- не понимать, какого формата результат вернулся из запроса.

Перед `practice.py` ты должен понимать:
1. какую роль играет Python, а какую - SQL;
2. зачем нужен `commit()`;
3. каков минимальный цикл работы с SQLite из Python.
