# Дата и время в SQL

## Когда это нужно
Без работы с датой и временем невозможно:
- фильтровать события по интервалам;
- строить отчёты по дням и месяцам;
- группировать активность по датам;
- считать простые временные сдвиги вроде "следующий день".

## Как об этом думать
Дата и время в SQL - это не просто текст для показа. Их нужно уметь:
- извлекать из timestamp нужную часть;
- сравнивать;
- группировать;
- преобразовывать к удобному формату.

В SQLite для этого чаще всего используются функции `date(...)`, `time(...)`, `datetime(...)` и `strftime(...)`.

## date(...)
`date(...)` возвращает только дату без времени.

Пример:
```sql
SELECT date(executed_at) AS day
FROM test_runs;
```

Если в `executed_at` хранится `2026-04-01 10:00:00`, результатом будет `2026-04-01`.

Это удобно для группировки по дням.

## strftime(...)
`strftime(...)` позволяет вытащить нужный формат даты и времени.

Пример:
```sql
SELECT strftime('%Y-%m', executed_at) AS month_bucket
FROM test_runs;
```

Это даёт bucket по месяцу, например `2026-04`.

Полезно, когда нужно строить отчёты по месяцам, дням, часам или другим частям timestamp.

## Простая арифметика дат
В SQLite можно сдвигать даты модификаторами.

Пример:
```sql
SELECT date('2026-04-01', '+1 day');
```

Результат: `2026-04-02`.

Это удобно для простых сценариев типа:
- следующий день;
- минус 7 дней;
- начало месяца.

## Как применять это в задачах
Если задача говорит:
- "посчитать события по дням" -> вероятно нужен `date(...)` + `GROUP BY`;
- "получить bucket по месяцу" -> нужен `strftime('%Y-%m', ...)`;
- "посчитать дату на следующий день" -> нужен `date(..., '+1 day')`.

## Частые ошибки
- работать с timestamp как с обычной строкой, не извлекая нужную часть;
- группировать по полному timestamp, когда нужен день или месяц;
- не понимать, что `date(...)` отбрасывает время;
- выбирать не тот формат в `strftime(...)`.
