# Практика на базовые запросы

## Зачем нужен этот день
До этого темы шли по одной. Но в реальной задаче почти никогда не бывает “чистого `WHERE` без всего остального”.
Обычно в одном запросе сразу сочетаются:
- выбор колонок;
- фильтрация;
- сортировка;
- простые функции;
- иногда ограничение по числу строк.

## Как подходить к задаче
Не пиши весь запрос сразу. Разбивай его мысленно на части:
1. какая таблица нужна;
2. какие строки должны остаться;
3. какие колонки нужно показать;
4. нужна ли сортировка;
5. нужен ли `LIMIT`.

## Почему это важнее, чем запомнить синтаксис
Синтаксис можно подсмотреть. Гораздо важнее научиться переводить условие задачи в SQL-логику.

Если задача говорит:
- “активные пользователи из web-команды” -> это фильтр;
- “отсортировать по имени” -> это `ORDER BY`;
- “только первые 3” -> это `LIMIT`.

## Как себя проверять
После написания запроса спроси себя:
- я точно выбрал правильную таблицу;
- фильтр соответствует условию буквально;
- порядок сортировки соответствует ожиданию;
- нет ли лишних колонок.

## Типичная ошибка этого дня
Главная ошибка - пытаться решать задачу “по памяти”, а не по смыслу. Если условие непонятно, лучше сначала сформулировать его обычным языком, а потом уже писать SQL.
