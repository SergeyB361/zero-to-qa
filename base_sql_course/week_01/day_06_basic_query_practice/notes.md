# Практика на базовые запросы

## Зачем нужен этот день
До этого темы шли по одной. Но в реальной задаче почти никогда не бывает "чистого `WHERE` без всего остального".

Обычно в одном запросе сразу сочетаются:
- выбор колонок;
- фильтрация;
- сортировка;
- простые функции;
- иногда ограничение по числу строк.

## Как подходить к задаче
Не пиши весь запрос сразу. Разбивай его мысленно на части:
1. какая таблица нужна;
2. какие строки должны остаться;
3. какие колонки нужно показать;
4. нужна ли сортировка;
5. нужен ли `LIMIT`.

## Как переводить условие задачи в SQL
Если задача говорит:
- "активные пользователи из web-команды" -> это фильтр;
- "отсортировать по имени" -> это `ORDER BY`;
- "только первые 3" -> это `LIMIT`;
- "показать длину названия" -> это функция вроде `LENGTH()`.

Смысл в том, чтобы сначала понять задачу обычным языком, а уже потом собирать SQL.

## Как себя проверять
После написания запроса спроси себя:
- я точно выбрал правильную таблицу;
- фильтр соответствует условию буквально;
- порядок сортировки соответствует ожиданию;
- нет ли лишних колонок;
- не потерял ли я важную часть условия.

## Что считается типичной ошибкой
Главная ошибка этого дня - пытаться решать задачу "по памяти", а не по смыслу.

Если условие непонятно, лучше сначала переформулировать его обычным языком и только потом писать SQL.

## Зачем это важнее, чем запомнить синтаксис
Синтаксис всегда можно подсмотреть. Гораздо важнее научиться выбирать нужную конструкцию под условие задачи.

Именно это отличает человека, который "видел SQL", от человека, который реально умеет им пользоваться.

## Что должно получиться после этого дня
После `practice.sql` у тебя должна появиться уверенность, что ты можешь:
- читать условие;
- разложить его на SQL-шаги;
- собрать понятный запрос без случайного перебора.
