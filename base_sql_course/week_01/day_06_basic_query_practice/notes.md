# Практика на базовые запросы

## Зачем это нужно
Этот день нужен, чтобы склеить вместе фильтрацию, сортировку, функции и базовые операции без перехода к JOIN.

## Что нужно понять
- комбинирование базовых конструкций
- чтение условий задачи
- проверка результата

## Рабочая логика
1. Определи, из каких таблиц ты читаешь данные.
2. Сузь выборку фильтрами.
3. Только потом добавляй сортировку, группировку или join.
4. Проверяй вывод на маленьком наборе данных.

## Примеры
### Пример 1 - Активные пользователи не из mobile
```sql
SELECT name FROM users WHERE is_active = 1 AND team != 'mobile' ORDER BY name;
```

### Пример 2 - Высокоприоритетные test case
```sql
SELECT title FROM test_cases WHERE priority = 'high' ORDER BY title;
```

### Пример 3 - Открытые или in_progress задачи
```sql
SELECT id, status FROM tasks WHERE status IN ('open', 'in_progress') ORDER BY id;
```

## Типичные ошибки
- писать сложный запрос без проверки маленьких частей
- не сверять вывод с исходными данными

## Практика
В `practice.py` есть функции для самостоятельной реализации:
- `high_priority_case_titles` - Верни названия test case с priority = high.
- `active_users_ordered` - Верни имена активных пользователей, отсортированных по team, затем name.
- `heavy_tasks` - Верни id задач с estimate_hours >= 5.

## Что дальше
Сначала запусти `examples.py`, затем реализуй функции из `practice.py` и сверь вывод с expected.
