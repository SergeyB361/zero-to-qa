# INSERT, UPDATE, DELETE

## Зачем это нужно
SQL нужен не только для чтения. В тестах и backend-задачах часто надо подготовить данные, изменить статус или удалить мусор после сценария.

## Что нужно понять
- INSERT
- UPDATE
- DELETE
- подготовка тестовых данных
- проверка результата после изменения

## Рабочая логика
1. Определи, из каких таблиц ты читаешь данные.
2. Сузь выборку фильтрами.
3. Только потом добавляй сортировку, группировку или join.
4. Проверяй вывод на маленьком наборе данных.

## Примеры
### Пример 1 - Добавить нового пользователя
```sql
INSERT INTO users (id, name, team, is_active) VALUES (5, 'Roma', 'api', 1);
```

### Пример 2 - Перевести задачу в closed
```sql
UPDATE tasks SET status = 'closed', closed_at = '2026-04-12' WHERE id = 1;
```

### Пример 3 - Удалить закрытый дефект
```sql
DELETE FROM defects WHERE id = 2;
```

## Типичные ошибки
- обновлять без `WHERE`
- не проверять, что изменения реально применились
- удалять данные без cleanup

## Практика
В `practice.py` есть функции для самостоятельной реализации:
- `insert_case_and_count` - Добавь новый test case и верни новое количество test_cases.
- `close_task_and_get_status` - Закрой задачу с id = 4 и верни её новый статус.
- `delete_closed_defects_and_count` - Удали закрытые дефекты и верни количество оставшихся дефектов.
