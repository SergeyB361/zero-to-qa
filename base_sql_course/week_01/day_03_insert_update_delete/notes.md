# INSERT, UPDATE, DELETE

## Когда это нужно
SQL нужен не только для чтения. В тестах и локальной отладке часто приходится:
- добавить тестовые данные;
- изменить статус записи;
- удалить временный мусор после сценария.

## Что делает каждая команда
`INSERT` добавляет новую строку.
`UPDATE` меняет существующие строки.
`DELETE` удаляет строки.

Это уже не просто чтение, а изменение состояния базы данных.

## Как мыслить безопасно
С любым изменяющим запросом полезно думать так:
1. какие строки я хочу затронуть;
2. как я ограничиваю их через `WHERE`;
3. как я проверю результат после изменения.

Особенно это важно для `UPDATE` и `DELETE`. Если забыть `WHERE`, можно изменить или удалить всю таблицу.

## Пример безопасного подхода
Вместо того чтобы сразу писать большой `UPDATE`, полезно сначала проверить выборку:
```sql
SELECT id, status FROM tasks WHERE id = 4;
```
а уже потом выполнять:
```sql
UPDATE tasks SET status = 'closed' WHERE id = 4;
```

## Почему это важно для QA
В тестах база часто выступает как часть setup/cleanup.
Ты создаёшь запись перед тестом, проверяешь результат сценария и затем очищаешь данные, чтобы следующий запуск не зависел от прошлого.

## Частые ошибки
- делать `UPDATE` без `WHERE`;
- не проверять, что строка действительно изменилась;
- оставлять временные записи после теста;
- забывать, что изменение данных - это уже побочный эффект, а не просто чтение.

## Что проверить перед практикой
Перед `practice.py` ты должен понимать:
- чем `INSERT` отличается от `UPDATE`;
- почему `DELETE` без `WHERE` опасен;
- почему после изменения данных нужен проверочный `SELECT`.
