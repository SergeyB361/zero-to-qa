# INSERT, UPDATE, DELETE

## Когда это нужно
`SELECT` читает данные. Но в реальной работе SQL нужен не только для чтения. Очень часто приходится:
- добавить тестовые данные перед сценарием;
- изменить статус записи после действия;
- удалить временные данные после проверки.

Именно для этого нужны `INSERT`, `UPDATE` и `DELETE`.

## Что делает каждая команда
- `INSERT` добавляет новые строки в таблицу.
- `UPDATE` меняет существующие строки.
- `DELETE` удаляет существующие строки.

Это уже не просто запрос к данным, а изменение состояния таблицы.

## INSERT: как добавить строку
Базовый синтаксис:
```sql
INSERT INTO table_name (col1, col2, col3)
VALUES (value1, value2, value3);
```

Как читать эту команду:
1. `INSERT INTO users` - в какую таблицу добавляем;
2. `(id, name, team, is_active)` - какие колонки заполняем;
3. `VALUES (...)` - какие значения записываем.

Пример:
```sql
INSERT INTO users (id, name, team, is_active)
VALUES (5, 'Roma', 'api', 1);
```

Когда применять:
- создать тестовые данные;
- добавить новую сущность в учебном dataset;
- подготовить строку для проверки `SELECT` или `JOIN`.

Как проверить результат:
```sql
SELECT id, name, team
FROM users
WHERE id = 5;
```

## UPDATE: как изменить существующие строки
Базовый синтаксис:
```sql
UPDATE table_name
SET col1 = value1, col2 = value2
WHERE condition;
```

Как читать эту команду:
1. `UPDATE tasks` - в какой таблице меняем данные;
2. `SET status = 'closed'` - что именно меняем;
3. `WHERE id = 4` - какие строки должны быть затронуты.

Пример:
```sql
UPDATE tasks
SET status = 'closed', closed_at = '2026-04-12'
WHERE id = 4;
```

Когда применять:
- поменять статус задачи или дефекта;
- обновить технический флаг;
- довести запись до нужного состояния для теста.

Главное правило: `UPDATE` почти всегда должен иметь `WHERE`.
Без `WHERE` изменятся все строки таблицы.

Как проверить результат:
```sql
SELECT id, status, closed_at
FROM tasks
WHERE id = 4;
```

## DELETE: как удалить строки
Базовый синтаксис:
```sql
DELETE FROM table_name
WHERE condition;
```

Как читать эту команду:
1. `DELETE FROM defects` - из какой таблицы удаляем;
2. `WHERE id = 2` - какие строки удаляем.

Пример:
```sql
DELETE FROM defects
WHERE id = 2;
```

Когда применять:
- cleanup после теста;
- удаление временных записей;
- очистка учебного dataset от лишних строк.

Главное правило здесь то же: `DELETE` без `WHERE` удалит всю таблицу.

Как проверить результат:
```sql
SELECT id, title
FROM defects
WHERE id = 2;
```
Если запрос больше не возвращает строку, удаление сработало.

## Безопасный workflow для изменяющих запросов
Нормальная привычка такая:

1. сначала сделать `SELECT` и убедиться, что ты нашёл нужные строки;
2. потом выполнить `INSERT`, `UPDATE` или `DELETE`;
3. потом ещё раз выполнить проверочный `SELECT`.

Пример для `UPDATE`:
```sql
SELECT id, status
FROM tasks
WHERE id = 4;
```

```sql
UPDATE tasks
SET status = 'closed'
WHERE id = 4;
```

```sql
SELECT id, status
FROM tasks
WHERE id = 4;
```

Так ты не работаешь вслепую.

## Почему это особенно важно для QA
В QA эти команды чаще всего нужны не для "ведения продовой базы руками", а для:
- setup тестовых данных;
- проверки промежуточного состояния;
- cleanup после сценария;
- локального воспроизведения ситуации.

То есть важно не просто знать синтаксис, а понимать безопасный рабочий цикл вокруг этих команд.

## Частые ошибки
- писать `UPDATE` без `WHERE`;
- писать `DELETE` без `WHERE`;
- не проверять, какие строки будут затронуты до изменения;
- забывать проверить результат после изменения;
- смешивать setup и cleanup так, что уже не ясно, что именно изменилось.

## Что проверить перед практикой
Перед `practice.sql` ты должен понимать:
1. как выглядит базовый синтаксис `INSERT`, `UPDATE`, `DELETE`;
2. зачем `WHERE` нужен для `UPDATE` и `DELETE`;
3. как проверить результат изменяющего запроса обычным `SELECT`.
