# Мини-проект: запросы к QA dataset

## Зачем нужен этот мини-проект
Это первая точка, где SQL перестаёт быть набором отдельных команд и начинает выглядеть как маленький рабочий toolkit.

## Что ты здесь тренируешь
В проекте повторяются все базовые идеи первой недели:
- чтение данных через `SELECT`;
- фильтрация через `WHERE`;
- сортировка и ограничение результата;
- аккуратный возврат данных из Python-функций.

## Как правильно проходить мини-проект
Не пытайся сразу реализовать весь файл.
Рабочий порядок такой:
1. открой `spec.md`;
2. реализуй одну функцию;
3. запусти файл и сравни результат с expected;
4. только потом переходи к следующей функции.

## На что смотреть в качестве решения
Хорошее решение здесь - это не “самый короткий SQL”, а решение, где:
- функция называется по смыслу;
- запрос читается без расшифровки;
- результат легко сравнить с expected;
- нет лишней постобработки в Python.

## Что будет считаться слабым решением
- неясные имена функций;
- тяжёлая логика в Python при простом SQL-вопросе;
- отсутствие проверки результата после каждого шага;
- случайный порядок строк там, где стоило явно отсортировать результат.

## Что дальше
Если этот мини-проект делается уверенно, значит неделя 1 реально усвоена, а не просто прочитана.
