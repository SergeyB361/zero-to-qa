# Мини-проект: запросы к QA dataset

## Зачем нужен этот мини-проект
Это первая точка, где SQL перестаёт быть набором отдельных конструкций и начинает выглядеть как маленький рабочий toolkit.

Здесь ты уже не тренируешь одну команду изолированно, а собираешь несколько осмысленных запросов к небольшому dataset.

## Что именно ты здесь тренируешь
В проекте повторяются базовые идеи первой недели:
- чтение данных через `SELECT`;
- фильтрация через `WHERE`;
- при необходимости сортировка и ограничение результата;
- аккуратная формулировка результата под конкретный вопрос.

## Как правильно проходить мини-проект
Рабочий порядок такой:
1. открой `spec.md` и прочитай все deliverables;
2. реализуй один запрос;
3. проверь, что результат соответствует expected;
4. только потом переходи к следующему запросу.

Не нужно пытаться решить весь файл одним заходом.

## На что смотреть в качестве решения
Хорошее решение здесь - не самый короткий SQL, а решение, в котором:
- каждый запрос называется и читается по смыслу;
- логика соответствует вопросу буквально;
- результат можно легко сравнить с expected;
- нет лишних колонок и лишних условий.

## Что будет считаться слабым решением
- запросы, которые случайно дают правильный результат только на текущем dataset;
- лишняя сортировка или отсутствие сортировки там, где порядок важен;
- смешение нескольких разных задач в одном запросе;
- непонятный SQL, который трудно объяснить обычным языком.

## Что должно остаться после проекта
Если этот мини-проект делается уверенно, значит `week_01` действительно усвоена:
- ты понимаешь базовую логику SQL;
- можешь читать и писать простые запросы;
- умеешь проверять себя по expected-результату.

Это и есть правильная база для перехода к агрегатам, `JOIN` и следующим неделям.
