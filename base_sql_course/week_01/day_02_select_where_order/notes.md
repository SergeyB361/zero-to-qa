# SELECT, WHERE, ORDER BY, LIMIT

## Когда это нужно
Это базовый набор команд для чтения данных. Почти любой SQL-запрос начинается именно отсюда: нужно выбрать таблицу, отфильтровать строки, отсортировать результат и, если нужно, взять только часть выборки.

Если этот слой не понятен, все следующие темы будут выглядеть как набор случайных фраз.

## Базовый синтаксис запроса
Самый типовой шаблон выглядит так:

```sql
SELECT col1, col2
FROM table_name
WHERE condition
ORDER BY col1 ASC
LIMIT 10;
```

Важно понимать не только как это написать, но и как это прочитать.

## Что делает каждая часть
### SELECT
Определяет, какие колонки ты хочешь увидеть в результате.

Пример:
```sql
SELECT id, name
```
Это значит: покажи только `id` и `name`.

### FROM
Показывает, из какой таблицы брать данные.

Пример:
```sql
FROM users
```
Это значит: работаем с таблицей `users`.

### WHERE
Оставляет только те строки, которые подходят под условие.

Пример:
```sql
WHERE is_active = 1
```
Это значит: оставить только активных пользователей.

### ORDER BY
Сортирует результат.

Пример:
```sql
ORDER BY name ASC
```
Это значит: отсортировать по имени по возрастанию.

Если написать `DESC`, порядок будет обратным.

### LIMIT
Ограничивает число строк в результате.

Пример:
```sql
LIMIT 3
```
Это значит: вернуть только первые 3 строки после всех остальных шагов.

## Как читать запрос целиком
Полезно мысленно разбирать запрос так:

1. из какой таблицы берём данные;
2. какие строки оставляем;
3. как сортируем оставшееся;
4. сколько строк возвращаем;
5. какие колонки показываем в результате.

Пример:
```sql
SELECT id, status
FROM tasks
WHERE status = 'open'
ORDER BY estimate_hours DESC
LIMIT 2;
```

Как это прочитать по смыслу:
- взять таблицу `tasks`;
- оставить только строки, где статус `open`;
- отсортировать их по `estimate_hours` сверху вниз;
- взять первые две строки;
- показать только `id` и `status`.

## Как применять это в задачах
Если условие говорит:
- "покажи имена пользователей" -> нужен `SELECT name`;
- "только активных" -> нужен `WHERE is_active = 1`;
- "отсортируй по имени" -> нужен `ORDER BY name`;
- "только первые 5" -> нужен `LIMIT 5`.

То есть SQL удобно строить от смысла задачи, а не пытаться вспомнить формулу целиком.

## Почему порядок важен
Новички часто читают SQL просто слева направо как текст. Но полезнее понимать, что `LIMIT` имеет смысл только после сортировки, а `WHERE` отбирает строки до финального результата.

Из-за этого:
- `ORDER BY ... LIMIT 3` и просто `LIMIT 3` — это не одно и то же;
- без `WHERE` можно получить слишком много строк;
- без `ORDER BY` `LIMIT` часто даёт просто первые попавшиеся строки, а не "самые нужные".

## Как выбирать колонки
Не выбирай больше, чем нужно. Если задача просит только `id` и `status`, не нужно тащить `SELECT *`.

Почему это важно:
- запрос читается проще;
- результат короче и понятнее;
- ты лучше контролируешь, что именно проверяешь.

## Частые ошибки
- забывать кавычки у строковых значений: нужно `'open'`, а не `open`;
- путать фильтрацию и сортировку;
- использовать `LIMIT` без понимания порядка строк;
- сортировать не по тому полю;
- брать `SELECT *`, когда нужны 1-2 колонки.
