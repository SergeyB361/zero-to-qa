# SELECT, WHERE, ORDER BY, LIMIT

## Когда это нужно
Это базовый рабочий набор для чтения данных. Почти любой SQL-запрос в работе QA или backend начинается именно отсюда.

## Что делает каждая часть
`SELECT` определяет, какие колонки ты хочешь увидеть.
`FROM` говорит, из какой таблицы брать данные.
`WHERE` отбрасывает ненужные строки.
`ORDER BY` сортирует результат.
`LIMIT` ограничивает количество строк в ответе.

## Как запрос выполняется по смыслу
Полезно мысленно читать запрос так:
1. выбрали таблицу;
2. отфильтровали строки;
3. отсортировали оставшееся;
4. оставили нужное число строк;
5. вывели нужные колонки.

Пример:
```sql
SELECT id, status
FROM tasks
WHERE status = 'open'
ORDER BY estimate_hours DESC
LIMIT 2;
```
Здесь база:
- берёт все строки из `tasks`;
- оставляет только `open`;
- сортирует их по `estimate_hours` сверху вниз;
- отдаёт только первые две.

## Почему порядок важен
Новички часто воспринимают SQL как линейный текст слева направо, но полезнее понимать смысл этапов. Тогда легче замечать ошибки: например, когда ты ограничил выборку не после сортировки, а пытаешься угадать результат “на глаз”.

## Как выбирать колонки
Не тяни лишнее. Если тебе нужны только `id` и `status`, не используй лишние поля. Это делает запрос понятнее и ближе к реальной инженерной практике.

## Частые ошибки
- забывать кавычки у строковых значений;
- путать `=` и `IN`;
- сортировать не по тому полю;
- использовать `LIMIT` без понимания, какие строки попадут после сортировки.

## Что проверить перед практикой
Ты должен понимать:
- что именно фильтрует `WHERE`;
- почему `ORDER BY` меняет только порядок строк, а не сами данные;
- почему `LIMIT` без сортировки часто даёт случайно полезный, но нестабильный результат.
