# DISTINCT, aliases, базовые SQL-функции

## Когда это нужно
На этом этапе запросы начинают быть не только рабочими, но и удобными для чтения.

Эти инструменты нужны, чтобы:
- убрать дубликаты;
- сделать результат понятнее по именам колонок;
- выполнить простое преобразование данных прямо в SQL.

## DISTINCT: убрать повторы
`DISTINCT` убирает повторяющиеся строки результата по выбранным колонкам.

Пример:
```sql
SELECT DISTINCT team
FROM users;
```

Это значит: показать не всех пользователей, а только уникальные значения `team`.

Если одна и та же команда встречается у нескольких пользователей, в результате она останется один раз.

## Когда DISTINCT уместен
Используй `DISTINCT`, когда тебя интересует набор уникальных значений, а не сами записи.

Например:
- уникальные команды;
- уникальные статусы;
- уникальные владельцы проектов.

## Aliases: переименовать колонку или таблицу
Alias — это временное имя внутри запроса.

Для колонки:
```sql
SELECT name AS user_name, team AS squad
FROM users;
```

Это делает результат понятнее: вместо сырого `name` ты видишь `user_name`.

Для таблицы alias особенно полезен в `JOIN`:
```sql
FROM tasks AS t
INNER JOIN users AS u ON t.assignee_id = u.id
```

## Зачем aliases нужны на практике
Aliases полезны в двух случаях:
1. сделать итоговую колонку читаемой;
2. сократить длинные имена таблиц в сложных запросах.

Это не косметика. Хороший alias помогает понять смысл результата без расшифровки.

## Базовые SQL-функции
SQL умеет не только возвращать данные, но и выполнять простые вычисления прямо в запросе.

Примеры:
- `COUNT()` — считает;
- `LENGTH()` — возвращает длину строки;
- `UPPER()` — переводит текст в верхний регистр.

Пример:
```sql
SELECT title, LENGTH(title) AS title_len
FROM test_cases;
```

Это значит: вернуть название тест-кейса и длину этого названия.

## Когда функция полезнее постобработки
Если преобразование простое и относится прямо к данным запроса, часто удобнее сделать его сразу в SQL, а не переносить в Python или ручную обработку.

## Частые ошибки
- использовать `DISTINCT`, не понимая, откуда взялись дубликаты;
- давать alias, которые ничего не объясняют;
- забывать, что функция применяется к конкретной колонке или значению;
- путать "уникальные строки" и "уникальные значения одной колонки".

## Что проверить перед практикой
Ты должен понимать:
1. чем `DISTINCT` отличается от обычного `SELECT`;
2. зачем нужен `AS`;
3. почему иногда проще вызвать `UPPER()` или `LENGTH()` в SQL, чем потом обрабатывать результат отдельно.
