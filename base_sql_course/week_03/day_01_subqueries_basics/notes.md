# Подзапросы: база



## Когда это нужно

Подзапрос нужен, когда часть ответа надо сначала вычислить отдельным запросом, а потом использовать внутри другого запроса.



## Как об этом думать

Подзапрос - это запрос внутри запроса. Его задача не в том, чтобы сделать SQL "умнее на вид", а в том, чтобы разбить логику на два шага.



Например:

1. сначала найти средний балл;

2. потом выбрать только тех пользователей, чей балл выше среднего.



Если написать это в один шаг без промежуточной идеи, логика развалится.



## Какие подзапросы бывают на базовом уровне

Для этого курса достаточно понимать два основных варианта:

- подзапрос возвращает одно значение;

- подзапрос возвращает набор значений.



Первый тип часто используется с `=`, `>`, `<`.

Второй тип - с `IN`.



## Пример мышления

Запрос:

```sql

SELECT name

FROM users

WHERE id IN (SELECT owner_id FROM projects);

```

по смыслу делает так:

1. внутренний запрос получает список `owner_id` из `projects`;

2. внешний запрос берёт только тех пользователей, чей `id` есть в этом списке.



## Когда подзапрос полезнее, чем `JOIN`

Не всегда нужен `JOIN`. Если тебе нужно просто сравнить значение с другой выборкой или проверить попадание в набор, подзапрос может быть понятнее.



Но подзапрос - это не "замена любому join". Это просто другой инструмент.



## Частые ошибки

- не понимать, что именно возвращает внутренний запрос: одно значение или много;

- использовать `=` там, где подзапрос возвращает несколько строк;

- писать подзапрос, хотя обычный `JOIN` читался бы проще;

- терять смысл запроса, потому что читаешь его только как синтаксис.



## Что проверить перед практикой

Перед `practice.sql` ты должен понимать:

1. зачем нужен подзапрос как отдельный шаг вычисления;

2. чем подзапрос с одним значением отличается от подзапроса со списком;

3. как по смыслу выполняется `WHERE id IN (SELECT ...)`.
