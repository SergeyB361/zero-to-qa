# EXISTS и NOT EXISTS



## Когда это нужно

`EXISTS` нужен, когда вопрос звучит как проверка существования: есть ли связанная запись, был ли хотя бы один запуск, есть ли хоть одна ошибка.



## Почему это не то же самое, что `IN`

`IN` хорошо работает, когда тебе нужен набор значений.

`EXISTS` лучше выражает идею "для этой строки существует подходящая запись".



На человеческом языке:

- `IN` сравнивает значение со списком;

- `EXISTS` проверяет сам факт существования связанной строки.



## Как читать `EXISTS`

Пример:

```sql

SELECT u.id, u.name

FROM users AS u

WHERE EXISTS (

    SELECT 1

    FROM tasks AS t

    WHERE t.assignee_id = u.id

);

```

По смыслу:

1. берём одного пользователя `u`;

2. запускаем внутреннюю проверку: есть ли хотя бы одна задача, где `assignee_id = u.id`;

3. если да - пользователь остаётся в результате.



Это и есть коррелированный подзапрос: внутренний запрос зависит от текущей строки внешнего запроса.



## Зачем нужен `NOT EXISTS`

`NOT EXISTS` - зеркальная версия. Она отлично подходит для поиска отсутствия:

- пользователи без задач;

- проекты без тестов;

- заказы без оплат.



Такие задачи в QA и аналитике встречаются постоянно.



## Почему `SELECT 1`

Внутри `EXISTS` неважно, что именно выбирать. SQL проверяет не значение, а наличие строки. Поэтому `SELECT 1` - просто компактная форма записи.



## Частые ошибки

- думать, что `EXISTS` возвращает данные из внутреннего запроса;

- не понимать связь между внешней и внутренней строкой;

- использовать `NOT IN`, когда из-за `NULL` можно получить неожиданное поведение;

- писать слишком сложный коррелированный подзапрос там, где логика ещё не понятна.
