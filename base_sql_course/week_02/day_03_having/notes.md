# HAVING



## Когда это нужно

`HAVING` нужен, когда ты хочешь отфильтровать не отдельные строки, а уже готовые группы.



## Ключевая разница между `WHERE` и `HAVING`

`WHERE` работает до группировки. Он решает, какие строки вообще попадут в расчёт.

`HAVING` работает после `GROUP BY`. Он решает, какие группы останутся в итоговом ответе.



Это главный смысл темы. Если его не понять, `HAVING` будет казаться просто ещё одним фильтром с другим названием.



## Как об этом думать на примере

Запрос:

```sql

SELECT assignee_id, COUNT(*)

FROM tasks

GROUP BY assignee_id

HAVING COUNT(*) >= 3;

```

по смыслу делает так:

1. берёт строки из `tasks`;

2. группирует их по `assignee_id`;

3. считает количество задач в каждой группе;

4. оставляет только тех исполнителей, у кого задач 3 и больше.



`WHERE COUNT(*) >= 3` здесь не подойдёт, потому что на этапе `WHERE` ещё нет никакого `COUNT(*)` по группе.



## Когда использовать оба сразу

Это нормальная ситуация:

- `WHERE` сужает исходные строки;

- `HAVING` сужает уже рассчитанные группы.



Например, можно сначала взять только `open`-задачи через `WHERE`, а потом через `HAVING` оставить только тех исполнителей, у кого таких задач больше двух.



## Где это нужно QA

Полезные сценарии:

- найти пользователей с большим числом ошибок;

- найти тест-кейсы, которые часто падали;

- оставить только проекты, где запусков больше заданного порога;

- строить отчёты по данным, а не по отдельным строкам.



## Частые ошибки

- пытаться использовать агрегат в `WHERE`;

- не понимать, что `HAVING` работает только после группировки;

- писать `HAVING` там, где достаточно обычного `WHERE`;

- забывать, что `HAVING` без `GROUP BY` встречается, но в базовом курсе так лучше не думать.
