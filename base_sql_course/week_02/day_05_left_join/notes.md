# LEFT JOIN



## Когда это нужно

`LEFT JOIN` нужен, когда важно сохранить все строки из левой таблицы, даже если в правой подходящая запись не найдена.



## Главная идея

`INNER JOIN` отвечает на вопрос: "где есть совпадения с обеих сторон?"

`LEFT JOIN` отвечает на другой вопрос: "покажи всё слева и, если получится, подставь данные справа".



Это очень полезно в QA, когда нужно находить отсутствие связи:

- задачи без исполнителя;

- проекты без владельца;

- тест-кейсы без запусков;

- пользователи без заказов.



## Что происходит по смыслу

Запрос:

```sql

SELECT t.id, u.name

FROM tasks AS t

LEFT JOIN users AS u ON t.assignee_id = u.id;

```

делает так:

1. берёт каждую строку из `tasks`;

2. пытается найти подходящую строку в `users`;

3. если находит - объединяет данные;

4. если не находит - всё равно оставляет строку `tasks`, но поля из `users` становятся `NULL`.



## Почему `NULL` справа - это важный сигнал

В `LEFT JOIN` `NULL` в правых колонках часто не ошибка, а полезная информация: связи нет.



Например, если после `LEFT JOIN users` колонка `u.id` равна `NULL`, это почти всегда означает, что соответствующий пользователь не найден.



## Как искать "сиротские" записи

Классический паттерн:

```sql

SELECT t.id

FROM tasks AS t

LEFT JOIN users AS u ON t.assignee_id = u.id

WHERE u.id IS NULL;

```

Смысл: возьми все задачи, попытайся найти пользователей и оставь только те строки, где справа никого не нашлось.



## Частые ошибки

- ожидать от `LEFT JOIN` такого же результата, как от `INNER JOIN`;

- фильтровать правую таблицу в `WHERE` неаккуратно и случайно превращать `LEFT JOIN` в `INNER JOIN`;

- не понимать, что `NULL` справа часто означает отсутствие связи, а не поломку SQL.



## Что проверить перед практикой

Перед `practice.sql` ты должен уметь объяснить:

1. чем `LEFT JOIN` отличается от `INNER JOIN`;

2. почему строки из левой таблицы сохраняются всегда;

3. как по `NULL` справа найти записи без пары.
