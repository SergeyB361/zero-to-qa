# CI Basics for Backend

## Когда тема нужна
Как только backend становится совместным проектом, недостаточно того, что он "у меня локально запускается".

Нужен автоматический сигнал качества на каждое изменение.

Для backend этот сигнал обычно включает:
- lint;
- tests;
- иногда миграции и smoke-check runtime.

## Как мыслить правильно
CI — это не просто YAML-файл. Это правило: что проект обязан доказать перед merge.

Хороший backend pipeline отвечает на вопросы:
1. что проверяется на каждый push или PR;
2. какие шаги обязательны;
3. что сохраняется после падения;
4. насколько быстро разработчик получает сигнал.

## Что обычно входит в минимальный pipeline
На базовом уровне для backend достаточно:
- checkout кода;
- setup Python;
- install dependencies;
- lint или compile/syntax check;
- test run;
- иногда отдельный шаг для migration sanity.

Не нужно делать гигантский enterprise pipeline раньше времени. Но базовый контракт должен быть явным.

## Почему миграции полезно упоминать отдельно
Для backend с БД миграции — это не факультативная деталь. Если код меняет модели, а миграции забыты, сервис может быть "зелёным" по юнит-тестам и при этом сломанным по runtime.

Поэтому даже простой CI должен хотя бы обозначать, где проверяется schema consistency.

## Что делает pipeline хорошим
- он короткий и читаемый;
- разделяет подготовку среды и сами проверки;
- отражает реальные риски проекта;
- даёт быстрый сигнал на PR.

## Как устроен этот урок
В этом дне примеры и практика завязаны на реальный workflow-файл:
- `backend-ci.example.yml` — эталонный CI;
- `backend-ci.practice.yml` — файл, который нужно довести до валидного содержимого.

Это методически сильнее, чем упражнение на Python-список шагов, потому что студент работает с настоящим delivery-артефактом.

## Типичные ошибки
- один giant step на всё подряд;
- нет отдельного шага для tests;
- забыты зависимости проекта или test requirements;
- CI проверяет только formatting, а runtime tests вообще не запускает;
- в pipeline не отражены миграции, хотя проект DB-heavy.

## Что нужно понять перед практикой
Перед `practice.py` должно быть ясно:
1. какие шаги минимально нужны backend pipeline;
2. почему tests и migrations нельзя считать второстепенными;
3. почему CI должен давать быстрый и понятный сигнал, а не просто существовать.
