# Capstone Prep

## Что это за день
Это не ещё одна тема. Это день выравнивания ожиданий перед финальным backend-service.

К этому моменту курс уже дал:
- layers;
- settings;
- SQLAlchemy + migrations;
- auth и roles;
- CRUD patterns;
- test DB thinking;
- compose и CI basics.

Теперь задача — не узнать новую технику, а собрать из этого понятный MVP scope.

## Что считается достаточным capstone
Хороший capstone на этом уровне не обязан быть production-ready во всём. Но он обязан быть инженерно цельным.

Минимальный набор:
- FastAPI app;
- SQLAlchemy models;
- Postgres-ready config;
- CRUD endpoints;
- auth/role layer;
- tests;
- Docker Compose;
- описанный запуск.

## Почему scope важнее лишних фич
Очень частая ошибка финальных проектов — добавить десять лишних возможностей и не довести базовые слои.

Для capstone важнее:
- целостность контракта;
- воспроизводимый запуск;
- понятная архитектура;
- наличие проверки качества.

То есть лучше один законченный сервис, чем полтора недоделанных направления.

## Как проверять readiness
Перед стартом capstone полезно ответить:
1. какие endpoint-ы входят в MVP;
2. какая auth-модель используется;
3. где живёт data layer;
4. как запускаются tests;
5. как поднимается runtime через Docker Compose.

Если на эти вопросы нет коротких ответов, проект ещё не готов к реализации.

## Типичные ошибки
- начинать писать код без зафиксированного MVP scope;
- не определить критерий готовности;
- смешать optional backlog и обязательный минимум;
- забыть про tests и runtime delivery до самого конца.

## Что нужно понять перед практикой
Перед `practice.py` должно быть ясно:
1. какие блоки capstone обязательны;
2. что считать MVP-границей;
3. почему prep — это не бюрократия, а способ не развалить финальный проект по дороге.
