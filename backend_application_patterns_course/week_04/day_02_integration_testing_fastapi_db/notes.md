# Integration Testing: FastAPI + DB

## Когда тема нужна
После unit-тестов хочется проверить уже не отдельную функцию, а связку:
- request приходит в FastAPI;
- dependency отдаёт session;
- service пишет в БД;
- endpoint возвращает корректный HTTP-ответ.

Это и есть основной практический смысл integration tests для backend.

## Как мыслить правильно
Хороший integration test отвечает на вопрос: работает ли реальный сервисный flow, если пройти его через HTTP и data layer вместе.

То есть тест проверяет не отдельный helper, а связку слоёв.

## Что такой тест должен покрывать
На этом уровне integration test обычно проверяет:
- status code;
- response payload;
- реальное изменение данных в БД;
- обработку ошибок на boundary route/service.

Если тест смотрит только JSON, но не проверяет данные в БД, он уже полезен, но не до конца закрывает сценарий.

## Почему `TestClient` здесь удобен
`TestClient` даёт настоящий HTTP-like flow без отдельного внешнего процесса.

Это значит, что можно прогнать:
- route;
- dependencies;
- Pydantic validation;
- service layer;
- DB session.

При этом тест остаётся быстрым и управляемым.

## Где проходит граница между unit и integration
Если ты мокнул repository и БД, это уже не integration test, а unit/service-level test.

Integration начинается там, где сервис реально ходит в тестовую БД и поднимается через приложение, а не через ручной вызов метода.

## Что особенно важно
Для таких тестов нужно контролировать:
- отдельную test DB strategy;
- предсказуемые seeds;
- отсутствие утечки данных между тестами.

Без этого integration tests быстро становятся flaky.

## Типичные ошибки
- называть integration test-ом тест без реальной БД;
- не проверять side effects в базе;
- использовать production-like config без isolation;
- строить тест только вокруг happy path.

## Что нужно понять перед практикой
Перед `practice.py` должно быть ясно:
1. что именно делает тест integration, а не просто endpoint-level smoke;
2. почему `TestClient` + test DB — практичное сочетание;
3. какие слои сценария должны реально участвовать в проверке.
