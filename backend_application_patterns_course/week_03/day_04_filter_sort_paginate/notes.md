# Filter, Sort, Paginate

## Когда тема нужна
Почти любой list endpoint быстро перестаёт быть "верни всё подряд".

Появляются запросы вида:
- покажи только `status=open`;
- отсортируй по `priority`;
- верни вторую страницу по 20 записей;
- сначала новые, потом старые.

Если этот слой не продуман, API становится либо неудобным, либо очень дорогим по данным.

## Как мыслить правильно
Полезная последовательность такая:
1. сначала filter сужает набор данных;
2. потом sort определяет порядок;
3. потом pagination режет уже отсортированный результат.

Если перепутать этот порядок, клиент получает неожиданные страницы и нестабильную навигацию.

## Почему pagination — это не косметика
Pagination нужна не только ради красоты UI.

Она решает реальные backend-задачи:
- ограничивает объём ответа;
- делает list endpoint предсказуемым;
- уменьшает нагрузку на БД и сеть;
- позволяет клиенту последовательно обходить большой набор данных.

## Что обычно достаточно на базовом уровне
На этом уровне полезно уметь:
- фильтровать по одному-двум полям;
- сортировать по whitelisted значениям;
- резать результат через `page/page_size` или `limit/offset`;
- возвращать не только `items`, но и метаинформацию (`total`, `page`, `page_size`).

## Почему sort должен быть whitelisted
Если клиент может передать любой `sort_by`, сервис быстро превращается в источник ошибок и случайных запросов.

Поэтому backend должен явно решать:
- какие поля разрешены для сортировки;
- какие значения считаются корректными;
- что делать при неизвестном параметре.

## Где это должно жить
- router принимает query params;
- service решает, как их интерпретировать;
- repository/DB layer выполняет уже нормализованный запрос.

Даже если в учебном примере всё считается в памяти, ментальная модель должна быть такой же, как для реальной БД.

## Типичные ошибки
- пагинировать до сортировки;
- сортировать по любому полю без контроля;
- возвращать все записи, а пагинацию делать на клиенте;
- забывать возвращать `total`, из-за чего клиент не понимает размер набора.

## Что нужно понять перед практикой
Перед `practice.py` должно быть ясно:
1. в каком порядке применяются filter, sort и paginate;
2. почему `sort_by` должен быть ограниченным контрактом;
3. почему list endpoint должен возвращать не только `items`, но и metadata.
