# Test Data Engineering, День 6 — Reusable datasets

## Когда это нужно

Не все данные нужно собирать на лету. Для части сценариев полезно иметь стабильные reusable datasets: небольшие, понятные наборы записей, на которых можно повторяемо проверять поведение системы.

## Как об этом думать

Хороший mental model: reusable dataset — это curated test data pack для повторяемых сценариев.

Он полезен, когда:
- нужен общий baseline для нескольких тестов;
- важно повторять аналитический или интеграционный сценарий на одном наборе;
- выгоднее хранить понятный срез данных, чем пересобирать его каждый раз.

## Что делает dataset хорошим

Хороший reusable dataset:
- небольшой и читаемый;
- покрывает важные варианты поведения;
- не содержит лишнего шума;
- имеет явное назначение.

То есть он должен быть explainable: по нему должно быть понятно, зачем он существует.

## Где это особенно полезно

- API/contract tests;
- аналитические отчёты;
- UI scenarios с предсказуемым состоянием;
- demos и regression baselines.

## Где ошибаются чаще всего

- datasets растут бесконтрольно;
- никто не знает, какие строки для чего нужны;
- данные устаревают, но всё ещё используются как baseline;
- reusable dataset подменяет собой все остальные стратегии работы с данными.

## Что важно перед практикой

Перед `practice.py` ты должен понимать:
1. reusable dataset нужен для повторяемости и ясности;
2. его ценность в curated составе, а не в объёме;
3. dataset должен быть versioned и понятен по назначению.

## Что делать дальше

1. Открой `examples.py` и посмотри, как reusable dataset помогает нескольким сценариям сразу.
2. Затем переходи к `practice.py`.
3. В каждом задании сначала решай, какой минимальный набор данных даст нужный coverage signal.
