# Bonus Advanced Python OOP, День 5 - __getattr__, __getattribute__, __setattr__

## Зачем это нужно

Обычно доступ к атрибутам в Python выглядит просто:

```python
obj.name
obj.status = "open"
```

Но иногда нужно перехватить этот доступ:
- если часть полей хранится динамически;
- если хочется логировать обращения;
- если нужно нормализовать данные при записи;
- если объект ведёт себя как proxy или view поверх другого объекта.

Для этого и существуют `__getattr__`, `__getattribute__` и `__setattr__`.

## Разница между тремя методами

### __getattr__

Вызывается только тогда, когда обычный поиск атрибута уже не нашёл значение.

Это хороший вариант для:
- fallback-логики;
- динамических полей;
- прокидывания доступа в словарь или payload.

Пример:

```python
def __getattr__(self, name):
    return self.payload[name]
```

## Когда __getattr__ удобен

Если у объекта есть словарь с данными:

```python
payload = {"status": "open", "priority": "high"}
```

то можно сделать:

```python
event.status
event.priority
```

через `__getattr__`, не создавая вручную отдельные свойства для каждого поля.

### __getattribute__

Вызывается всегда, вообще при любом чтении атрибута.

Это гораздо более мощный и опасный инструмент.

С его помощью можно:
- логировать все обращения;
- делать proxy;
- менять поведение чтения глобально;
- подменять значения на лету.

Но именно здесь легко поймать бесконечную рекурсию.

## Главная ловушка __getattribute__

Если внутри `__getattribute__` написать:

```python
self.name
```

то это снова вызовет `__getattribute__`, и код уйдёт в рекурсию.

Поэтому внутри обычно нужно использовать:

```python
object.__getattribute__(self, name)
```

Это базовый безопасный способ достать реальный атрибут.

### __setattr__

Вызывается при любой записи атрибута:

```python
obj.email = "  USER@EXAMPLE.COM  "
```

Через `__setattr__` можно:
- очищать строку;
- приводить значения к lowercase;
- запрещать определённые записи;
- отслеживать изменения полей.

## Где это реально полезно

### 1. Dynamic payload view

Если объект оборачивает словарь:

```python
response.status
response.error_code
```

можно отдавать значения из `payload` через `__getattr__`.

### 2. Logging proxy

Через `__getattribute__` можно фиксировать, к каким полям чаще обращаются.

### 3. Normalization on write

Через `__setattr__` можно автоматически:
- убирать пробелы;
- нормализовать email;
- приводить статус к единому формату.

## Когда использовать __getattr__

Используй `__getattr__`, если:
- нужно обработать только отсутствующие атрибуты;
- есть простой fallback;
- не нужен полный контроль над любым чтением.

Это более безопасный вариант.

## Когда использовать __getattribute__

Используй `__getattribute__`, если:
- нужен контроль всех чтений;
- ты точно понимаешь, как избежать рекурсии;
- другого механизма недостаточно.

Это инструмент не “на каждый день”.

## Когда использовать __setattr__

Используй `__setattr__`, если:
- логика записи должна быть общей для всех присваиваний;
- нужно централизованно валидировать или нормализовать значения;
- отдельные `property` для каждого поля были бы слишком шумными.

## Частые ошибки

### 1. Путать __getattr__ и __getattribute__

`__getattr__` - только fallback.

`__getattribute__` - перехват всего чтения.

Это принципиально разные уровни вмешательства.

### 2. Делать self.attr внутри __getattribute__

Так почти гарантированно получится рекурсия.

### 3. Делать слишком много логики в __setattr__

Если каждая запись атрибута запускает сложный каскад правил, модель становится
трудной для понимания.

### 4. Прятать “магию” без необходимости

Если задачу проще решить через обычный метод или `property`, лучше выбрать
более явный вариант.

## Практическое правило для курса

Полезная лестница такая:

1. сначала обычные атрибуты;
2. потом `property`;
3. потом `__getattr__`, если нужен fallback;
4. только потом `__getattribute__`, если действительно нужен глобальный перехват.
