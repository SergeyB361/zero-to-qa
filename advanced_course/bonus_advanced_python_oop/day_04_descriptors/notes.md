# Bonus Advanced Python OOP, День 4 - Дескрипторы и property

## Зачем это нужно

`property` удобно, когда нужно контролировать одно конкретное поле в одном классе.

Но если одна и та же логика нужна в нескольких моделях, `property` быстро начинает
дублироваться. Типичный пример:
- проверка, что строка не пустая;
- проверка, что число положительное;
- ограничение набора допустимых значений;
- логика чтения/записи поля через один общий механизм.

Для этого и нужны дескрипторы.

## Что такое дескриптор

Дескриптор - это объект, который реализует один или несколько специальных методов:
- `__get__`
- `__set__`
- `__delete__`

Если такой объект лежит в атрибуте класса, Python использует его как посредника
при доступе к полю экземпляра.

Идея простая:
- ты пишешь `user.name`;
- Python не всегда читает значение напрямую из `user.__dict__`;
- сначала он может передать чтение объекту-дескриптору.

## Минимальный пример

```python
class PositiveInt:
    def __set_name__(self, owner, name):
        self.storage_name = "_" + name

    def __get__(self, instance, owner):
        if instance is None:
            return self
        return getattr(instance, self.storage_name)

    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError("must be positive")
        setattr(instance, self.storage_name, value)
```

Если такой дескриптор положить в класс:

```python
class RetryPolicy:
    retries = PositiveInt()
```

то запись `policy.retries = 3` будет проходить через `PositiveInt.__set__`.

## Что делает __set_name__

`__set_name__` вызывается один раз при создании класса.

Он особенно полезен, когда дескриптору нужно узнать имя поля, под которым его
сохранили:

```python
title = NonEmptyString()
```

Тогда дескриптор понимает, что работает с полем `title`, и может хранить данные,
например, в `_title`.

## Data descriptor и non-data descriptor

### Data descriptor

Если объект реализует `__set__` или `__delete__`, это data descriptor.

Он имеет более высокий приоритет при поиске атрибута.

Это значит:
- Python сначала идёт в data descriptor;
- и только потом смотрит в `instance.__dict__`.

### Non-data descriptor

Если объект реализует только `__get__`, это non-data descriptor.

У него приоритет ниже:
- сначала Python может найти обычный атрибут экземпляра;
- и только потом использовать descriptor.

## Почему property - это тоже descriptor

`property` по сути уже реализует descriptor protocol.

Это важно понимать:
- `property` не магия;
- это просто готовая удобная обёртка;
- descriptor - более общий и мощный механизм.

Хорошее правило:
- если логика нужна только одному полю в одном классе, начни с `property`;
- если логика должна переиспользоваться между классами, смотри в сторону дескрипторов.

## Где дескрипторы полезны в реальном коде

### 1. Переиспользуемая валидация

Например:
- непустые строки;
- положительные числа;
- допустимые статусы;
- идентификаторы правильного формата.

### 2. Нормализация данных

Можно автоматически:
- обрезать пробелы;
- приводить email к lowercase;
- приводить к единому формату.

### 3. Контролируемый доступ к полям

Например:
- read-only поле;
- lazy loading;
- проверка инвариантов доменной модели.

## Как Python ищет атрибут с descriptor

Упрощённо порядок такой:

1. data descriptor в классе;
2. `instance.__dict__`;
3. non-data descriptor или обычный атрибут класса;
4. `__getattr__`, если ничего не найдено.

Это важно, потому что descriptor - часть общего механизма доступа к атрибутам.

## Частые ошибки

### 1. Хранить значение внутри самого descriptor

Если написать так:

```python
self.value = value
```

внутри descriptor, то одно значение может случайно стать общим для всех объектов.

Правильно хранить данные в экземпляре:

```python
setattr(instance, self.storage_name, value)
```

### 2. Забыть случай `instance is None`

В `__get__` это важный случай.

Когда доступ идёт через класс, а не через объект, стоит вернуть сам descriptor:

```python
if instance is None:
    return self
```

### 3. Использовать descriptors там, где хватает property

Descriptor мощнее, но и сложнее.

Если нет переиспользуемой логики, `property` обычно читается лучше.

## Практическое правило для курса

Сначала отвечай на вопрос:

1. Это правило нужно одному полю или многим?
2. Я хочу просто спрятать поле или переиспользовать механизм?
3. Не проще ли здесь обычный `property`?

Если ответ:
- логика повторяется;
- нужна единая валидация;
- хочется reusable building block,

то descriptor оправдан.
