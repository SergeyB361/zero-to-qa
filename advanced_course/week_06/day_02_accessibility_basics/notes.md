# UI: качество и масштабирование, День 2 — Accessibility basics

## Когда это нужно

Даже базовые accessibility-проверки помогают обнаружить реальные дефекты интерфейса: недоступные кнопки, потерю фокуса, некорректные роли и проблемы навигации с клавиатуры.

На advanced-уровне важно воспринимать accessibility не как отдельную “добровольную тему”, а как часть качества интерфейса.

## Как об этом думать

Хороший mental model: accessibility — это проверка того, может ли пользователь с разными ограничениями и разными способами взаимодействия пользоваться интерфейсом предсказуемо.

На базовом уровне QA особенно полезно смотреть на:
- roles и accessible names;
- keyboard navigation;
- focus order;
- форменные controls и labels;
- понятные тексты ошибок.

## Что это даёт practically

- улучшает testability UI через более семантические локаторы;
- снижает риск реальных usability defects;
- даёт более сильные UI contracts;
- делает интерфейс устойчивее не только для assistive tech, но и вообще для пользователей.

## Частые ошибки

- считать accessibility только проблемой фронтенда;
- ограничиваться автоматическим сканером;
- не проверять keyboard flow;
- путать accessibility checks с purely visual polish.

## Что важно перед практикой

Перед `practice.py` ты должен понимать:
1. accessibility — часть функционального качества интерфейса;
2. keyboard, focus и semantics дают сильный практический сигнал;
3. даже базовые accessibility checks уже полезны для зрелого UI-suite.
