# API: reliability и integration, День 1 — Async API и polling

## Когда это нужно

Не все API возвращают готовый результат сразу. В реальных системах часть операций запускает асинхронную обработку: задача создаётся, а результат появляется позже.

Именно в таких сценариях нужны polling и async-aware тесты.

## Как об этом думать

Хороший mental model:
- первый запрос запускает работу;
- система возвращает идентификатор операции или промежуточный статус;
- клиент периодически проверяет состояние, пока операция не завершится или не выйдет в timeout.

То есть тест здесь должен проверять не один ответ, а жизненный цикл операции во времени.

## Что важно тестировать

- старт операции;
- промежуточные статусы;
- успешное завершение;
- отказ или timeout;
- корректное поведение при слишком ранней проверке результата.

## Что делает polling корректным

Хороший polling учитывает:
- интервал между попытками;
- общий timeout;
- terminal states;
- ожидаемое degraded behavior, если операция не завершилась.

Без этого тест становится либо flaky, либо бесконечным ожиданием.

## Частые ошибки

- использовать fixed sleep вместо polling-логики;
- не ограничивать timeout;
- не различать transient и terminal states;
- проверять только happy completion.

## Что важно перед практикой

Перед `practice.py` ты должен понимать:
1. async API требует проверки state progression, а не одного ответа;
2. polling — это controlled waiting, а не случайная пауза;
3. timeout и failure path так же важны, как и успешное завершение.
