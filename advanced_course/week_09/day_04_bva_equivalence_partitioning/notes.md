# Test Design и Requirements Engineering, День 4 — BVA и Equivalence Partitioning

## Когда это нужно

Если у правила есть диапазоны, допустимые и недопустимые классы значений, то тестировать все возможные входы бессмысленно. Здесь нужны техники, которые уменьшают пространство данных без потери смысла.

Именно это делают Boundary Value Analysis и Equivalence Partitioning.

## Как об этом думать

Equivalence Partitioning делит входы на классы, внутри которых система должна вести себя одинаково.

Boundary Value Analysis усиливает это, фокусируясь на границах таких классов, где дефекты особенно вероятны.

Хороший mental model:
- partition отвечает на вопрос “какие классы значений эквивалентны по поведению?”
- boundary отвечает на вопрос “где внутри этих классов самые рискованные точки?”

## Где это особенно полезно

- диапазоны чисел и дат;
- длина строк и списков;
- лимиты, квоты, пороги;
- eligibility rules;
- валидация форм и API payloads.

## Что это даёт practically

- уменьшает число тестов без потери силы сигнала;
- помогает не забыть критические границы;
- делает test design более explainable;
- усиливает validation coverage.

## Частые ошибки

- брать только крайние значения и забывать про классы эквивалентности;
- не различать допустимые и недопустимые partitions;
- проверять только “на границе”, но не рядом с ней;
- не связывать boundary с реальным правилом системы.

## Что важно перед практикой

Перед `practice.py` ты должен понимать:
1. partitions уменьшают пространство входов осмысленно;
2. boundaries — особенно рискованные точки внутри этих классов;
3. сильный test design сочетает обе техники, а не выбирает одну случайно.

1. Открой `examples.py` и посмотри, как диапазон раскладывается на partitions и boundary values.
2. Затем переходи к `practice.py`.
3. В каждом задании сначала определи классы значений, а потом ищи их критические границы.
