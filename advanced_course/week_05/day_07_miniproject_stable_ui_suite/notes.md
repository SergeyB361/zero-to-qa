# UI: продвинутый уровень, День 7 — Мини-проект: Stable UI suite

## Что это за день

Это мини-проект про поддерживаемый и устойчивый UI-suite, а не про набор случайных браузерных тестов.

Здесь нужно соединить:
- auth state reuse;
- network interception;
- правильные waits;
- locator strategy;
- page object architecture;
- debugging-friendly artifacts.

## Что здесь проверяется

Мини-проект проверяет, умеешь ли ты:
- строить UI-suite слоями;
- снижать flaky risk осознанно;
- отделять сценарий от механики;
- делать результат пригодным для CI и расследования падений.

## Как правильно проходить

1. Сначала прочитай `spec.md`.
2. Затем выдели основные flaky risks UI-flow.
3. Реши, где нужен auth reuse, где network control, где page objects.
4. После этого собери suite как архитектурно связное решение.

## Что считается хорошим результатом

По сильному решению видно:
- как устроены страницы и компоненты;
- как стабилизированы ожидания и данные;
- какие артефакты останутся после падения;
- почему suite можно поддерживать при развитии продукта.

## На что обратить внимание

- не лечи всё `sleep`-ами;
- не делай page layer слишком умным;
- не подменяй реальный риск чрезмерным interception;
- следи, чтобы stability и maintainability были частью дизайна, а не постфактум патчем.
